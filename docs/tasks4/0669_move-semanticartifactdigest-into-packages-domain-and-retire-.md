## 0669. Move semanticArtifactDigest into packages/domain and retire the ranked-key mirror

### Background

Follow-up from the I8 verifyall re-audit (2026-08-25). `semanticArtifactDigest` — the function
ADR-079 makes cache validity depend on — lives in `plugins/sp/scripts/history-anatomy-cache.ts:163`,
outside `packages/domain`, while the type it canonicalizes (`HistoryArtifact`) lives in
`packages/domain/src/analytics/artifact.ts:203`.

The script therefore hand-maintains a mirror of the artifact's shape: `RANKED_ARTIFACT_KEYS`
(`history-anatomy-cache.ts:131`) names the arrays whose ORDER is evidence (bounded leaderboards) so
canonicalization does not sort them. Nothing keeps that mirror in sync with the type.

**The drift is proven, not hypothetical.** Two ranked arrays were missing from the list for months:

| Array | Ranked since | Missing until |
| --- | --- | --- |
| `CacheWasteStat.topSteps` — "largest offenders, bounded by the same `top`" (`artifact.ts:161`) | 0581 | 2026-08-25 |
| `DerivedVariables.bottlenecks` — "rank bottlenecks by ms descending" (`derived.ts:345`) | 0554 | 2026-08-25 |

**Neither was exploitable**, and the record should say so plainly: every entry in both lists carries
its own sort key, so `analyze` cannot emit the same entries in a different order — a reordering
implies a value change, which changes the digest anyway. The 2026-08-25 fix added both keys for
correctness-of-intent and consistency, not to close a live false-hit.

**The risk is the next one.** A ranked array whose order is NOT determined by its entries — ties
broken by insertion order, or a list ordered by an external key — would be silently sorted away, and
the digest would report `hit` on changed evidence. That is the one failure ADR-079 exists to prevent.

**The mirror is actually mirrored twice.** `plugins/sp/tests/history-anatomy-cache.test.ts:73`
re-declares the same six ranked keys as a literal `rankedKeys` array in its drift-guard test, so the
test that exists to catch drift is itself a hand-maintained copy of the thing that drifts.

Secondary instance of the same seam: `ELEVEN_SECTIONS` (`history-anatomy-cache.ts:88`) and
`FINDING_FIELDS` (`:102`) are re-declared in the script as local constants duplicating
`plugins/sp/skills/history-anatomy/references/report-contract.md`. **Corrected premise (verified
2026-08-25):** nothing ties the two together. `plugins/sp/tests/skill-structure.test.ts:964` asserts
only that `report-contract.md` *names* the eleven sections and nine finding fields — it never reads
the script's constants, so the script side can drift from the markdown without any test failing.

**Constraint that shaped the original placement (do not regress it).** The script is ADR-065
"standard contract": no `packages/` import, no `Bun.*` global, a committed `.mjs` twin generated by
`superskill script convert sp <rel>` that runs under bare `node` on an agent machine that has only
the plugin. Any fix must preserve that — the twin cannot gain a runtime dependency on the monorepo.

### Requirements

- [x] R1. `semanticArtifactDigest` and its canonicalization rules have a single owner in
      `packages/domain/src/analytics/`, beside the `HistoryArtifact` type they canonicalize. The
      ranked-versus-set classification is derived from, or co-located with, the artifact definition —
      not retyped as a second list.
- [x] R2. The plugin script consumes that owner without gaining a runtime dependency on the
      monorepo: ADR-065 standard contract is preserved (no `packages/` import surviving into the
      committed `.mjs` twin, no `Bun.*` global, `bun run script-contract-check` green, the twin still
      runs under bare `node` on a plugin-only machine).
- [x] R3. Adding a new array field to `HistoryArtifact` without classifying it as ranked or set
      fails a test — the drift class is closed, not merely the two known instances.
- [x] R4. Digest values are unchanged for every currently ranked and set array, so no published
      report's recorded `artifactDigest` is invalidated by the move. A migration that silently
      invalidates every existing cache is a regression, not a refactor.
- [x] R5. `ELEVEN_SECTIONS` and `FINDING_FIELDS` are assessed against the same seam: either given a
      single owner or explicitly recorded as a deliberate duplication with the reason, so the choice
      is documented rather than incidental.
- [x] R6. `docs/04_DESIGN.md` records the resulting ownership boundary in the same commit (T3), and
      ADR-079 gains an amendment noting where digest authority now lives.

### Q&A

**Q: R1 puts `semanticArtifactDigest` in `packages/domain`, but its only consumer is a plugin script
that cannot import the monorepo. Is that still the right owner?**
**Closed: yes — with the consequence recorded.** Measured 2026-08-25:
`superskill script convert sp <rel>` (the ADR-065 twin generator) **fails to bundle** an
`@gobing-ai/spur-domain` import — it exits `Bundle failed` — while relative `../lib/*.ts` and
`../lib/*.mjs` imports bundle and inline correctly and run under bare `node`. So the domain owner
will have exactly one consumer, reached through a generated file rather than an import. The smaller
alternative — leave `canonicalize`/`semanticArtifactDigest` in the script and move only the
ranked-versus-set classification — was considered and **rejected**: R1's AC says the digest
implementation "lives in the same package as the type it canonicalizes", and splitting the rules
from the function is what produced this drift in the first place. The generated-copy cost is the
price of that AC and is paid once.

**Q: Does the ranked-versus-set classification have to be hand-listed at all?**
**Closed: no — it is type-derived, and this was proven against the current tree.** A recursive
mapped type over `HistoryArtifact` yields the complete set of array-valued property names anywhere
in the nested tree; an exhaustive `Record<ArtifactArrayKey, 'ranked' | 'set'>` then fails `tsc` and
names the offender when a new array field is added. Verified 2026-08-25 by compiling the type in
`packages/domain`: with keys missing, `tsc` reported *"missing the following properties from type
'Record<ArtifactArrayKey, "set" | "ranked">': phases, bottlenecks, tools, skills, and 14 more"*; with
all 18 classified, the package typechecks clean. This is R3's gate — compile-time, not convention.

**Q: Will the move change any published report's recorded `artifactDigest`?**
**Closed: no, and it is measurable in advance.** The 18-key classification's ranked subset is exactly
today's six `RANKED_ARTIFACT_KEYS` (`byTool`, `bySession`, `topStepsByTokens`, `topStepsByDuration`,
`topSteps`, `bottlenecks`); the other twelve are sets, which `canonicalize` already sorts. Keys the
classification does not name keep today's behaviour (sort), so arbitrary JSON digests identically
too. R4 is therefore a property to *prove with a fixture test*, not a migration to plan.

**Q: `ELEVEN_SECTIONS` / `FINDING_FIELDS` (R5) — resolve or record?**
**Closed: resolve, by the cheapest correct route.** The premise that a string-matching test held them
together is false (see Background), so "record the duplication" would be recording an unguarded
copy. Extend the existing `skill-structure.test.ts` assertion to read the script's two constants and
require `report-contract.md` to name every entry of each — one test edit, no new module, no
generated file. Full single-owner treatment for the report vocabulary is **deferred**: it would need
a second generated file for a vocabulary that has drifted zero times.

**Q: Deferred with owner.** The twin-staleness hole — `script-contract-check` compares the twin's
mtime to `history-anatomy-cache.ts` only, so a change to the domain source plus a regenerated
`plugins/sp/lib/` file does not mark the twin stale. Not closed by ordering alone; the R2 bare-`node`
fixture test (below) is the backstop that fails on a stale twin. Widening `script-contract-check` to
follow transitive sources is **out of scope** for this task and belongs to feature I with ADR-065.

### Design

**WHAT.** Give the semantic artifact digest one authored owner in `packages/domain/src/analytics/`,
beside `HistoryArtifact`, with the ranked-versus-set classification derived from the type itself; the
plugin script consumes a **generated** copy through a relative import, so the ADR-065 twin keeps
running under bare `node` with no monorepo dependency.

**The classification is the whole mechanism — state it once.**

```ts
type ArrayKeys<T> = T extends readonly unknown[]
    ? never
    : T extends object
      ? { [K in keyof T]-?: NonNullable<T[K]> extends readonly unknown[] ? K : ArrayKeys<NonNullable<T[K]>> }[keyof T]
      : never;
export type ArtifactArrayKey = Extract<ArrayKeys<HistoryArtifact>, string>;
```

The 18 keys, frozen: **ranked (6)** `byTool`, `bySession`, `topStepsByTokens`, `topStepsByDuration`,
`topSteps`, `bottlenecks`; **set (12)** `coverage`, `daily`, `loops`, `warnings`, `pairings`,
`ladderSnapshot`, `stepSupport`, `phases`, `tools`, `skills`, `sources`, `models`. A key the
classification does not name keeps today's behaviour (sorted), so digests over arbitrary JSON are
unchanged — that is what makes R4 hold by construction.

**Test intent (the three that carry the requirements).**

1. **R3 — compile-time.** The exhaustive record *is* the gate: adding an array field to
   `HistoryArtifact` without classifying it fails `bun run lint` (`tsc --noEmit`) naming the field.
   Add one test asserting `ARTIFACT_ARRAY_CLASSIFICATION` covers every `ArtifactArrayKey`, so the
   failure also surfaces as a named test failure per the AC.
2. **R4 — digest parity.** Freeze a fixture artifact and its pre-move digest as a literal hex string
   in the test; assert the post-move implementation reproduces it byte-for-byte. Capture the literal
   from the current implementation **before** deleting it.
3. **R2 — the twin actually runs.** Spawn `node plugins/sp/scripts/history-anatomy-cache.mjs` over a
   fixture artifact and compare its digest to the domain implementation's. This is the backstop for
   the staleness hole named in Q&A: a stale twin fails here even though `script-contract-check` only
   compares the twin against its direct `.ts` source.

**Anti-patterns — do not implement.**

- Do **not** add `@gobing-ai/spur-domain` (or any `packages/` path) to a `plugins/sp/scripts/`
  import. It does not bundle — the twin build fails outright, and a `--external` workaround would
  ship a twin that crashes on a plugin-only machine.
- Do **not** hand-write the ranked list a second time in `plugins/sp/lib/`. The file is generated
  output; if it is ever edited by hand the seam is back.
- Do **not** hand-maintain `rankedKeys` in the drift-guard test. Deriving it from the classification
  is the point; a third mirror re-creates the defect inside its own guard.
- Do **not** widen `canonicalize`'s behaviour while moving it (no new excluded keys, no changed
  `generatedAt`/`validatedAt`/`baselineArtifactDigest` handling, no sort-stability change). Any
  behaviour change invalidates every published report's digest — that is R4's failure mode.
- Do **not** re-scope `script-contract-check` to follow transitive sources; deferred in Q&A.
- Do **not** move `ELEVEN_SECTIONS` / `FINDING_FIELDS` into a generated module — R5 is closed by
  extending an existing test, not by a second build artifact.

**Cross-task.** `dependencies: []` — nothing upstream. Leaves nothing for a dependent task: the
staleness-gate widening and the report-vocabulary single-owner treatment are both recorded as
deferred in Q&A with feature I / ADR-065 as the owner, not handed to a successor WBS.
