## 0650. Config 1.2: retire .spur/workflows and .spur/templates from seed, symlinks and shipped surfaces

### Background
Split from 0648. This slice removes the project-local workflow and template copies once
[0648](0648_config-1-2-two-tier-workflow-resolution-project-path-then-b.md) has given the CLI
a bundled-tree fallback, and repoints the shipped docs that name the old path.

#### Blast radius to record before starting

Dropping `workflows/**` and `templates/bdd/**` from the project seed changes what **every
consumer project** receives from `spur init`, not just this monorepo. That is the intended
consequence of the operator's ruling — 0648 made the bundled tree the fallback, so the copies
are dead weight — but it is a wider change than "unlink two symlinks here" and belongs in the
same commit as the doc updates that explain it.
### Requirements
- [ ] R1. `workflows/**` leaves the project seed: the 9 workflow entries in
      `scaffold-manifest.ts:44-55` are removed and `workflows/**` leaves the
      `listBundledProjectSeedFiles()` keep-set (`bundled-config.ts:136-140`), so
      `spur self init` no longer creates `.spur/workflows/`.

- [ ] R2. `templates/bdd/**` leaves the project seed the same way — **but only after** the
      four live consumers at `spur-dev/SKILL.md:224`, `planning-workflow.md:60` and
      `ac-style-guide.md:172,213` resolve the template through the bundled tree instead of a
      hardcoded `.spur/templates/bdd/gherkin.md` path. Removing the seed first breaks the BDD
      template lookup, which today has no fallback.

- [ ] R3. The `.spur/workflows` and `.spur/templates` symlinks are removed from this
      monorepo. `.spur/rules`, `.spur/tasks` and `.spur/plugins` are left exactly as they are.

- [ ] R4. No shipped `plugins/sp` command or skill markdown invokes a workflow by a
      `.spur/workflows/<name>.yaml` path. Scope is the 23 tracked `plugins/**/*.md` files
      plus the `plugins/sp/scripts` and `plugins/sp/tests` that assert on those strings.
      `docs/tasks*` historical records are explicitly out of scope — they are dated evidence,
      not live instructions. `apps/cli/plugins/**` and `apps/cli/config/**` are regenerated by
      `build:bundle`, never hand-edited.

- [ ] R5. `config/workflows/wayfinder-resolution.yaml:73` — which shells
      `$spurBin workflow validate .spur/workflows/wayfinder-resolution.yaml` — and its
      `config/workflow-composition-baseline.json:722` baseline entry are updated together, so
      the composition baseline does not fail on the changed invocation string.

- [ ] R6. The two-tier model is recorded where the old one is documented:
      `docs/04_DESIGN.md` §2.3 (the monorepo path model that describes the symlink) and
      `AGENTS.md` (the "Workflow YAML (monorepo self-dev)" paragraph naming `.spur/workflows/`
      as the runtime path). Surface code and `docs/04_DESIGN.md` land in the same commit (T3).

- [ ] R7. `bun run spur-check` green, `spur task check --corpus` green, and `bun run test-cf`
      unaffected. The composition baseline and the surface-drift inventory both pass.

### Q&A
#### Rulings applied

- **Unlink `.spur/templates` and `.spur/workflows`; keep `rules`, `tasks`, `plugins`.**
  Operator, 2026-08-23. The earlier objection — that unlinking redirects self-dev to a stale
  copy — was withdrawn once the fallback target became the *bundled* tree rather than the
  global one: `bundledConfigRoot()` resolves to repo-root `config/` in this monorepo, so an
  unlinked path reads the live working-tree SSOT, not a snapshot.

- **Two tiers, not three.** Operator, 2026-08-23. Recorded in full in
  [0649](0649_config-1-2-idempotent-spur-self-init-and-pre-a4-global-confi.md) Q&A.

#### Raised and accepted

**The seed change is wider than the unlink.** Dropping `workflows/**` and `templates/bdd/**`
from the project seed changes what every consumer project receives from `spur init`, not just
this repo. Recorded in Background § Blast radius; the operator's ruling covers it, and R6
requires the change be documented in the same commit.

#### Answered by verification

- *Would `spur self init` undo the unlink?* Yes, today — `scaffold-manifest.ts:44-55` plus the
  `listBundledProjectSeedFiles()` keep-set recreate `.spur/workflows/` as real copies, which
  would then shadow the bundled tier. R1 is what makes R3 stick.
- *Can `.spur/templates` go at the same time as `.spur/workflows`?* Not in the same step. The
  BDD template has four live consumers and no resolver with a fallback, unlike task templates
  (`task.ts:1422`). R2 sequences the repoint before the drop.
- *Are all 66 files in scope?* No. 23 tracked `plugins/**/*.md` plus the asserting scripts and
  tests are in scope; `docs/tasks*` are dated evidence and stay; `apps/cli/plugins/**` and
  `apps/cli/config/**` are gitignored build output.
### Design
#### Frozen decision

Unlink, do not deprecate. 0648 made the bundled tree the fallback, so a project-local copy is
no longer a fallback tier — it is a **shadow** that silently wins over the bundled copy and
pins the project to whatever was seeded on its first init. That is the staleness this whole
effort is removing, so the copies go rather than being kept "for compatibility".

#### Order of operations — the one sequencing trap

R2 before R3, and R1/R2 before the unlink. Doing it in the wrong order breaks the tree:

1. R1 — drop `workflows/**` from the seed.
2. R2 — repoint the four BDD template consumers, **then** drop `templates/bdd/**` from the seed.
3. R3 — unlink both directories.
4. R4/R5 — rewrite the shipped surfaces and the baseline together.
5. R6 — record the model in `docs/04_DESIGN.md` §2.3 and `AGENTS.md`.

Unlinking first leaves the repo with no workflows at all until 0648's fallback is exercised;
dropping `templates/bdd` before R2 breaks AC authoring with no error message pointing at why.

#### Anti-patterns to avoid

- **`rm -rf .spur/workflows` — never.** These are symlinks; `rm -rf` follows them and deletes
  `config/workflows/`, the tracked SSOT. Use `unlink`.
- **Do not edit `apps/cli/plugins/**` or `apps/cli/config/**`.** Gitignored `build:bundle`
  output (`.gitignore:80,84`); they will re-appear from the tracked tree.
- **Do not rewrite `docs/tasks*`.** Those are dated evidence records; a task that said
  `.spur/workflows/` in July was correct in July. Rewriting history is a separate
  docs-hygiene question, and A4 already parks it as such.
- **Do not remove `.spur/rules`, `.spur/tasks`, `.spur/plugins`.** Operator ruling: rules
  resolve against project folder structure (0641), and the other two are unrelated to this
  effort.
- **Do not change `workflows.paths` config semantics.** That key drives `workflow list`
  discovery. Out of scope here and in 0648.
