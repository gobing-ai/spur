  dependency resolution is unchanged. `bun install --frozen-lockfile` succeeds on the merged tree.
- AST comparison of old and moved service implementations finds 180 function/method bodies
  unchanged after ignoring comments, whitespace and collaborator receiver qualification.
  The four exceptions were read separately: `record` passes the facade host to close-audit
  reconciliation; `createEngineService` extracts fleet dependency composition; `executeRun`
  extracts preflight and capability parsing; `statCwd` becomes a free function receiving context.
  Their validation order, error returns and dependency values remain equivalent.
- All public constructor/method signatures on the three facades match the baseline:
  TaskService 19, WorkflowAppService 18, AgentService 11. The package barrel is unchanged.
- CLI AST comparison finds 271 unchanged function/callback bodies across task, workflow and agent.
  Remaining differences are noun registration split into per-verb functions, an explicit context
  argument replacing the workflow-local service factory, and equivalent best-effort batch cleanup.
  Registration ordering, option definitions and shared exports were inspected at the new indexes.
- Cross-cutting command inventories now enumerate both flat files and noun folders. Runtime-boundary
  exemptions follow the moved implementation files; public command placement checks recognize folders.

## Security, efficiency and architecture

Agent launch preflight retains fleet ground-truth checks, cwd/mode/timeout validation and
capability parsing before dispatch. Invocation sanitization and lifecycle cleanup moved with their
implementations. Workflow cleanup retains the existing realpath confinement and ownership checks.
Task write, parent-feature, dependency-freeze and close-audit guards remain behind the public facade.

The new collaborators group substantial operations rather than add public APIs. Imports from
collaborators back to service definitions are type-only; host references preserve public-method
callbacks and overrides. Resolution and run execution share one resolver per AgentService, preserving
its warning and roster state. No new dependency, storage format or transport contract was introduced.
The existing mutable fresh-roster override is unchanged; this review did not redesign its concurrency.
