## 1070. Stamp inline action provenance and project it

### Background

Implements feature E72 R8, "Host-reported and estimated action durations are labelled", and R9 (@edge), "Rows recorded before the provenance stamp read as unlabelled". Inline-driver action rows are written after the fact by the host session, so their `duration_ms` is host-reported and sometimes estimated, while engine rows are measured by the engine. The projection has to say which is which so the Trace tab (1071, AC7) can label them. Depends on 1069, which creates `workflowProgressProjectionSchema`. Design satellite: `docs/design/run-record-contract.md` § Feature E72.

Verified current state (2026-10-03):

- The inline write path is `packages/app/src/services/inline-run-setup.ts`:
  - `InlineRunTraceInput` (:1121) has runId, close, node, kind, reason?, status, ok and durationMs.
  - `runInlineRunTrace` (:1180) calls `writer.recordAction({ runId, node, kind, status, ok, durationMs })` around :1236.
  - `InlineRunActionEntry` (:1306) is `{ node, kind, status: 'done'|'failed', ok, durationMs }`.
  - `runInlineRunTraceBatch` (:1331) reads and validates every row before any write: it destructures `{ node, kind, status, ok, durationMs }` at :1354, runs type checks at :1355-1367, pushes the entry at :1368, then loops `writer.recordAction` from ~:1389.
- The writer is `packages/app/src/workflow/action-trace.ts`:
  - `ActionTraceBoundary` already has `result?: unknown` (:62) and `redactor?` (:63).
  - `recordAction` persists it through `saveActionFinalize(..., boundary.result, boundary.redactor)` into `action_runs.result_json`.
  - `createWorkflowActionTraceWriter(db, recordFailure)` is at :409.
  - No writer or schema change is needed.
- Redaction: `applyRedactor` keeps a plain record as-is and wraps a non-record as `{ value }`. `defaultActionRedactor` only touches `data.stdout`/`data.stderr` for kind `shell`, so `{ provenance, estimated }` survives intact.
- Engine rows: the engine writes its own action result into `result_json`, which is non-null and has no `provenance` key. So "absent stamp" means "no `provenance === 'host-reported'` key", **not** "null `result_json`".
- The projection is `packages/app/src/workflow/progress-projection.ts`:
  - `WorkflowActionAttempt` is near the top.
  - Attempts are built at :433-440 from `matchingRow` (`ActionRunRow`, `packages/domain/src/dao/action-run-dao.ts:4`, which already selects `result_json`).
- The plugin script is `plugins/sp/scripts/inline-run-setup.ts`. In its argv loop (~:118-131; `--persist-out` at :129), only `--fingerprint/--action/--close/--decide/--persist-out` are booleans. **Any other flag consumes the next argv as its value**, so `--estimated` must go in the boolean branch.
  - The `--action` path is ~:213-221.
  - The `--actions-file` path rejects other mode flags.
  - The `.mjs` twin (`inline-run-setup.mjs`) is generated by `bun run build:scripts`, which runs `build:plugin-lib` and then `superskill script convert sp inline-run-setup.ts`.
- Driver reference: `plugins/sp/skills/spur-dev/references/inline-pipeline-driver.md:344` and :628-660 (`--action`, `--actions-file` rows `[{node,kind,status,ok,durationMs}]`).
- The CLI contract text for the progress payload is at `docs/design/cli-contracts.md:672-680`, and the attempt field list is at :676.

  - `estimated = provenance === 'host-reported' && parsed?.estimated === true`
  - Null, unparseable or engine `result_json` gives `unknown`/`false` and never throws or adds a diagnostic.
- [ ] R5. Engine writes stay byte-identical. No engine, `DbWorkflowPersistenceAdapter` or migration change.
- [ ] R6. Contract and docs:

  - The 1069 assignability guard stays green.

  - `inline-pipeline-driver.md` documents `--estimated` (use it when the duration was not measured around the action) and the optional row field.

#### Q&A entry — 2026-10-04T03:01:11.035Z

- **Q: Where does the stamp live?** A: In the existing `action_runs.result_json`, through the writer's existing `result` boundary field (`action-trace.ts:61`). There is no migration and no new column. A display hint does not justify schema churn.
- **Q: How is an engine row told apart from a legacy inline row?** A: It isn't, and it doesn't need to be. Both read `unknown`, which R9 specifies as unlabelled. Stamping engine rows as `measured` is out of scope (R5 keeps engine writes unchanged). An `'engine'` enum value can be added later without breaking anything.
- **Q: Why is `estimated` only meaningful with `host-reported`?** A: The engine never estimates. Forcing `estimated=false` on `unknown` rows stops a malformed legacy blob from showing an estimated badge.
- **Q: Does the argv parser need care?** A: Yes. The fallback branch (`flags.set(flag, argv[++i])`) treats every unknown flag as taking a value. If `--estimated` is not in the boolean branch, `--estimated --ok true` silently sets `estimated='--ok'` and loses `--ok`. A test covers this ordering.
- **Q: Who decides that a duration is estimated?** A: The host driver. It passes `--estimated` when it did not time the action, for example when it reconstructs durations after a subagent returns. This task adds only the plumbing and the documentation, not a heuristic.
- **Q: Does the plugin standalone contract hold?** A: The script still imports only builtins and the resolved app entry; the new logic lives in `packages/app`. Rebuild the twin with `bun run build:scripts`. Do not hand-edit the `.mjs`.

### Design

- Chosen: stamp `{ provenance: 'host-reported', estimated }` into `result_json` through `recordAction`'s `result`, and derive the two fields in the projection. The change is additive and needs no migration.
- Rejected:
  - A new `action_runs` column, which needs a migration for a display hint.
  - An engine-side `measured` stamp, which changes engine writes and is out of scope.
  - Inferring provenance from `kind` or node names, which is a fragile heuristic.
- Invariants:
  - Batch validation stays all-or-nothing.
  - The redaction pipeline is unchanged (records pass through).
  - The projection never throws on `result_json`.
  - Engine rows are byte-identical.
- Key signatures:
  ```ts
  // packages/app/src/workflow/progress-projection.ts
  export interface WorkflowActionAttempt { ...existing; provenance: 'host-reported' | 'unknown'; estimated: boolean; }
  function readProvenance(resultJson: string | null): { provenance: 'host-reported' | 'unknown'; estimated: boolean } {
      if (resultJson === null) return { provenance: 'unknown', estimated: false };
      try {
          const parsed = JSON.parse(resultJson) as { provenance?: unknown; estimated?: unknown } | null;
          if (parsed?.provenance !== 'host-reported') return { provenance: 'unknown', estimated: false };
          return { provenance: 'host-reported', estimated: parsed.estimated === true };
      } catch {
          return { provenance: 'unknown', estimated: false };
      }
  }
  ```
