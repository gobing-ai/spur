## 1020. Extend the CLI-surface parity gate to docs/help and docs/help2

### Background

A 2026-09-30 session re-aligned `docs/help` (commit `b2f6691a4`) and `docs/help2` (uncommitted at
filing time) with the live `spur` CLI by hand. Both trees had drifted with no gate catching it:

- `docs/help/spur-cli-matrix.md` still listed the removed `team` noun and `agent create|edit|delete`,
  and claimed 48 verbs / 72 cells (live: 10 nouns, 51 unique verbs, 71 cells).
- `docs/help/how_to_use_spur_for_daily_software_development.md` §4 quick reference used the legacy
  `spur init|status|migrate|serve` spellings and named `--strict-core` as the done gate.
- `docs/help2` was missing live verbs (`agent status`, `agent usage`, `projects clean`) and flags
  (`task update --estimate-hours|--assignee|--provenance-bypass`, `task check --precheck`,
  `workflow continue --answer-text`, `workflow trace --timeout`, `--server`, `--fleet`, `--port`).

`plugins/sp/tests/cli-surface-parity.test.ts` gates only `plugins/sp/skills/spur-cli` and
`spur-dev` against live `--help`; the help docs have no equivalent. Those fixes are already applied
and are out of scope here — this task adds the gate so the drift cannot recur silently.

One related stale line was left untouched in the session: `config/workflows/task-pipeline.yaml:47`
still documents the `testing → done` guard as `spur task check <wbs> --strict-core`; the lifecycle
guard is `--as done` (`config/workflows/task-lifecycle.yaml:86,93`). It was deferred because
`apps/cli/config/` is generated from `config/workflows/` by `build:bundle`.

### Requirements

- [ ] R1. A test fails when a `spur <noun> <verb>` invocation in `docs/help/**` or `docs/help2/**` names a noun, verb, or flag absent from live `--help`. The hidden aliases `spur init|maintain|migrate|serve|status` and the hidden `agent loop` are allow-listed.
- [ ] R2. The same test fails when a live verb or flag is undocumented in the owning per-noun page (`docs/help/cmd_<noun>.md`, `docs/help2/<noun>.md`; `self` verbs map to their five verb pages). `--help` and `--json-envelope` are exempt.
- [ ] R3. The noun×verb table and summary counts in `docs/help/spur-cli-matrix.md` are checked against the live surface instead of trusted as hand-maintained.
- [ ] R4. The `testing → done` guard comment at `config/workflows/task-pipeline.yaml:47` names `--as done`, and the bundled copy is regenerated via `bun run --filter @gobing-ai/spur build:bundle`.
- [ ] R5. The implementation reuses the live-surface capture already used by `plugins/sp/tests/cli-surface-parity.test.ts`; it adds no public CLI verb and no dependency.

### Acceptance Criteria

- [ ] AC1: Adding `spur team start` to a `docs/help2` page makes the new test fail naming the file and token.
- [ ] AC2: Removing the `--precheck` mention from `docs/help2/task.md` makes the new test fail naming `task check --precheck`.
- [ ] AC3: Changing a verb count in `docs/help/spur-cli-matrix.md` makes the matrix check fail (or the file is regenerated byte-identically by its generator).
- [ ] AC4: `rg -n 'strict-core' config/workflows/task-pipeline.yaml` returns no match, and the bundled copy under `apps/cli/config/` matches after `build:bundle`.
- [ ] AC5: `bun run spur-check` passes on the final tree.

### Design

One new test file, `plugins/sp/tests/help-docs-parity.test.ts`, beside the existing
`cli-surface-parity.test.ts` and using the same `captureCliSurface` live capture (one capture per
command path, cached). No production code changes.

- **Live surface:** walk root → nouns → verbs via `--help`, yielding `{noun: {verb: flags[]}}`.
- **R1 (doc → CLI):** scan fenced code blocks and inline code spans in `docs/help/**/*.md` and
  `docs/help2/**/*.md` for `spur <noun> [<verb>] [--flag…]`; assert each noun/verb/flag exists.
  Allow-list: the five hidden aliases, `agent loop`, and lines documenting removed surface
  (`docs/help/environment_variables.md` removed-env table, `cmd_workflow.md` `--var` "no such form" note).
- **R2 (CLI → doc):** per noun, read the owning page(s) and assert every live verb and flag appears.
  Page map: `docs/help/cmd_<noun>.md` and `docs/help2/<noun>.md`; `self` → `init|status|serve|migrate|maintain` pages.
- **R3 (matrix):** parse the table in `docs/help/spur-cli-matrix.md`; assert the ✅ cells, the
  `Verb count` row, and the Summary counts equal the live surface.
- **R4:** comment-only edit in `config/workflows/task-pipeline.yaml`, then `build:bundle`.

Failures report sorted `documentedNotOnCli` / `onCliNotDocumented` lists with file paths, matching
the existing parity test's failure shape.

7. Run `bun run spur-check`.
