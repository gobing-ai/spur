## 0950. Wire the residual sweep into task-pipeline: base capture, verify fold, done settle, failed report

### Background

Depends on the residual scanner task (same feature). This task wires the scanner into `config/workflows/task-pipeline.yaml` so `/sp:dev-run` and `/sp:dev-runall` close leftovers through the existing remediation loop, with no new state and no new model query.

Premises (verified 2026-09-24):
- States: precheck :161, implement :211, test :287, test-fix :343, test-recheck :391, review :418, verify :470, record :540, done :592, failed :620 (config/workflows/task-pipeline.yaml).
- Verify derives the verdict with `$spurBin task verdict` (config/workflows/task-pipeline.yaml:529-531), then one jq action binds the proof block using `.verdict` for `stages.verification.status` (config/workflows/task-pipeline.yaml:535-537). The fold must run between them.
- verify→test-fix fires when the verdict is non-PASS and `<wbs>-test-fix-attempt` < `qualityGateMaxFixAttempts` (config/workflows/task-pipeline.yaml:811-821); otherwise verify→failed (:822-829). test-fix appends the verdict JSON to the gate log (:360) and passes `--findings "${vars.gateFindings}"` read from `<wbs>-test-gate.findings` (:366, :378).
- The fix counter resets only on quality-gate `run` (plugins/sp/scripts/quality-gate.ts:12), so a fresh `/sp:dev-run` gets a fresh budget.
- record's FIRST action `run.artifact` registers `<wbs>-verdict.json` against the proof digest (config/workflows/task-pipeline.yaml:563-569). Nothing may rewrite the verdict or create task files before that registration, which is why settle runs on `done` entry (:592-619).
- `failed` has no onEnter today (config/workflows/task-pipeline.yaml:620-623); `done` does (:596-619).
- Scripts are resolved repo-first, then via `superskill script path sp <name>.mjs`, failing closed (config/workflows/task-pipeline.yaml:341).
- `/sp:dev-fixall` takes `--gate-log` and `--findings` (plugins/sp/commands/dev-fixall.md:19-20).
- `apps/cli/config/` workflow copies are generated by `bun run --filter @gobing-ai/spur build:bundle` (AGENTS.md: "Workflow YAML SSOT is config/workflows/").

### Requirements

- [x] R1. precheck writes `git rev-parse HEAD` to `.spur/run/<wbs>-base.sha` only when that file is absent, so a resumed or re-entered run keeps its original base.
- [x] R2. verify runs `residual-scan scan` and `residual-scan fold` (repo-first, then superskill twin, failing closed like quality-gate) after `task verdict` and before the jq proof bind. A blocking residual therefore turns PASS into PARTIAL and takes the existing verify→test-fix edge while attempts remain.
- [x] R3. test-fix passes the residual list to `/sp:dev-fixall` through the merged `<wbs>-test-gate.findings` anchors and by appending `<wbs>-residuals.json` to the gate log. dev-fixall.md documents that residual items are fix targets and that the fixer may write `.spur/run/<wbs>-residual-deferrals.json` `{id, reason}` entries only for P3 findings or diff markers it cannot fix inside the task.
- [x] R4. done entry runs `residual-scan settle <wbs>` after the done transition as a best-effort action (exit 0; failure printed with a re-run command).
- [x] R5. failed entry runs `residual-scan report <wbs>` (exit 0), so a run that exhausts its fix budget on residuals leaves the report and a recovery line while the task stays `wip`.
- [x] R6. Regenerate bundled workflow copies and keep all existing task-pipeline definition and resilience tests green; add tests for the new actions and edges.

### Design

Contract owner: `docs/design/task-residual-sweep.md` (§Pipeline flow, §Terminal path). No new state, transition or model-bearing action.

Decisions:
- Each new action is a `kind: shell` with the same repo-first/twin/fail-closed resolution used by quality-gate at config/workflows/task-pipeline.yaml:341. Add a `# (d) residual-scan.ts owns …` comment in the file's style.
- scan+fold is one hard action. A scanner crash must fail verify closed rather than silently certify, because the verify→failed catch-all already routes a missing or malformed verdict.
- settle and report are soft (`exit 0`). They run after certification or at a terminal state and must never change the outcome.
- dev-fixall's pipeline input line stays unchanged; residual anchors arrive through the existing findings file and gate log.
- Anti-patterns: do not touch the verify→record guard, the `run.artifact` options, `qualityGateMaxFixAttempts`, or the verify agent input (`--fix none` stays).
