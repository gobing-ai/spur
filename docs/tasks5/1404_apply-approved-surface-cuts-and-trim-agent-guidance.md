## 1404. Apply approved surface cuts and trim agent guidance

### Background

Approved cuts reduce token load and routing ambiguity. 1394 adds the MCP-first rule, which is driven by tool presence, to `sp:spur-cli`, `cross-cutting.md` and the AGENTS.md routing table.

**Refine corrections (2026-11-17)**
- "Trim AGENTS.md routing and spur-cli for MCP-capable agents" → 1394 closed against per-agent guidance: the rule is driven by tool presence. → The trim removes only rows and lines that reference cut surfaces, plus guidance that the 1403 approval list names as superseded by `mcp-tools.md`. There is no per-agent variant.
- "Delete or merge approved surfaces" → plugin surfaces are referenced from many places:
  - `plugins/sp/README.md` (the `/sp:dev-*` index)
  - other skills and commands

#### Q&A entry — 2026-11-18T06:16:05.378Z

- **Consent for removing slash commands?** The 1403 approval entry is the consent. The AGENTS.md public-surface rule covers `spur` nouns and verbs, which this task doesn't touch.
- **Deprecation period?** No. Cuts are zero-use by evidence, so there's nobody to warn. A merge's CHANGELOG line names the replacement.

### Design

**WHAT.** Deletion over addition, driven only by the 1403 approval entry.

**WHY.** Every surface that survives costs tokens in every agent session. Removing a surface without sweeping its references leaves dangling routing, which is worse than keeping it.

**WHERE.**
- `plugins/sp/{commands,skills,agents}/`
- `plugins/sp/README.md`
- `AGENTS.md`
- `config/templates/AGENTS.md`
- `plugins/sp/skills/spur-cli/`
- `CHANGELOG.md`

**Anti-patterns.**
- No cut outside the approval list.
- No hand-edited generated adapters.
- No weakening of parity tests to make a deletion pass; fix the reference instead.
- No per-agent AGENTS.md variants.

### Plan

- [ ] Step 2: apply deletes and merges, then the AGENTS.md and template edits.
- [ ] Step 3: run the R4 gates and the superskill dry-run, and add the CHANGELOG lines.
