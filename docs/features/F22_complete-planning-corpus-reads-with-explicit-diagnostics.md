# F22: Complete planning corpus reads with explicit diagnostics

## Goal

Make task and feature read operations share complete, operation-scoped Markdown inputs so unreadable work is visible and cannot silently drive lifecycle decisions.

## Scope

In scope: W1 complete planning reads, explicit read diagnostics, operation-scoped parsed snapshots and their CLI/Board/lifecycle consumers.

Out of scope: persistent indexes, a second database authority, new write paths, corpus checker policy changes, and speculative caching.

W1: distinguish absent optional directories from failed reads; expose diagnostics; refuse lifecycle derivation on incomplete relevant inputs; reuse TaskLocator and MarkdownDocument in one operation-scoped parsed/indexed snapshot. Keep Markdown authoritative and writes in PlanningWriteService. No persistent shadow database or long-lived cache.

## Acceptance Criteria

```gherkin
Feature: Complete planning corpus reads with explicit diagnostics

  @core
  Scenario: R1 — Incomplete planning input cannot silently drive lifecycle state
    Given a done task and an unreadable todo task linked to the same feature

  @core

    Given registered task folders with aliases, duplicate identifiers, and cross-folder dependencies

    Then each relevant file is parsed once and duplicate identifiers and dependencies remain visible with actionable diagnostics
```
