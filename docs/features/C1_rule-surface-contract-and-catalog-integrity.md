# C1: Rule surface contract and catalog integrity

## Goal
Make the existing `spur rule` surface an explicit, verifiable contract and keep the repository-owned rule catalog documentation aligned with the shipped preset composition.
## Scope
**In scope:**

- `spur rule run|validate|list|trace` behavior already shipped by the CLI
- local rule/preset YAML under `config/rules` and its first-layer resolution
- `@gobing-ai/ts-rule-engine` integration and rule-run persistence
- catalog documentation accuracy for shipped presets, categories, and transitional helpers

**Out of scope:**

- new CLI verbs, flags, evaluators, resolvers, or formatters
- changes to rule bodies, preset composition, or engine behavior
- global and bundled rule layers beyond verifying their resolution precedence
- agent procedures for scanning, adding, or refining rules
