# G73: Cooperative fleet participation: hook lifecycle and guest join

## Goal

Members report lifecycle (working / idle / blocked) from host hooks so the strategy stops dispatching to an agent waiting on a human, and a live interactive session can join the fleet as a guest occupant that pulls inbox work through its own continuation hook (ADR-057 and ADR-121 amendments). Codex parity is decided by a spike first. Consented verbs: `spur agent join`, `leave`, `report` (D6). Plan: `docs/plans/2026-10-04-agent-fleet-inbox-redesign.md` §3.2 items 12–14.

## Scope

- In: `sp` plugin SessionStart/UserPromptSubmit/Stop hook glue; `spur agent report|join|leave`; event `agent.lifecycle.changed`; guest occupant registration and lease; `fleet-join` skill; Claude Stop-hook delivery; Codex hooks / `codex app-server` spike.
- Out: keystroke injection, PTY ownership, PID-attach (ADR-057); guests receiving constrained stages without attestation (ADR-102).

## Acceptance Criteria

```gherkin
Feature: Cooperative fleet participation: hook lifecycle and guest join

  Scenario: R1 — Agents report lifecycle through hooks
    Given a fleet member whose host fires SessionStart, UserPromptSubmit and Stop hooks
    When the hooks run with SPUR_SPEC_ID set
    Then spur agent report records monotonic states, emits agent.lifecycle.changed, and the strategy treats blocked as unavailable
    And outside a fleet the hooks do nothing and never slow the agent

  Scenario: R2 — Codex parity is decided by evidence
    Given the Codex hook and app-server surfaces
    When the spike runs
    Then a note records go or no-go for Stop-hook blocking and for app-server as a persistent member mode

  Scenario: R3 — A live session joins the fleet cooperatively
    Given an interactive Claude session
    When it runs spur agent join and the fleet-join skill
    Then it is a guest occupant addressable by id only, receives inbox work at turn end through the Stop hook, replies through spur message, and is released by spur agent leave or lease expiry
    And it never receives a stage that requires unattested capabilities
```
