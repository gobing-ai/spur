# K3: Project registry freshness: purge non-existent projects, kill orphaned serve ports, and clean worktree leftovers

## Goal

Ensure `~/.config/spur/projects.json` remains clean and accurate by automatically purging deleted project and worktree folders, terminating lingering background processes on occupied ports, and integrating comprehensive cleanup across `ProjectRegistry`, the `spur projects` CLI, and `plugins/sp` worktree lifecycles.

## Scope

- In:
  - New `refreshProjects` function on `ProjectRegistry` (and matching CLI support) to verify each registered project directory exists on disk and remove non-existent entries atomically.
  - Port and process reclamation: for deleted project paths whose registered port > 0, check if the port is occupied, discover the listening process ID, and terminate it cleanly (TERM then bounded wait and KILL if needed, excluding self/parent).
  - Calling refresh logic during standard operations: automatically during `ProjectRegistry.list()` (or project listing/start) and via explicit CLI verb (`spur projects clean` / `refresh`).
  - Comprehensive review and enhancement of `plugins/sp` worktree lifecycles (`execution-batch.md` WT-4/WT-5, single-task worktrees, branch workflows) to ensure worktrees added to `projects.json` are dereferenced and cleaned up on merge or removal.
  - Robust error handling and cross-platform process termination (macOS and Linux).
- Out:
  - Modifying SQLite database schemas (`spur.db`) or task/feature corpus schemas.
  - General process managers or supervisors for non-Spur services.
  - Changing git branch merging or fast-forward strategies.
