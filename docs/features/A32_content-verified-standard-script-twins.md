# A32: Content-verified standard-script twins

## Goal

`script-contract-check` proves every ADR-065 standard-script `.mjs` twin was built from the **current** `.ts` source by comparing content, not file mtimes. Git does not preserve mtimes, so today a stale committed twin passes after any fresh clone/checkout, and the only thing the rule was built to catch goes undetected in CI and worktrees.

## Scope

- In: replace the mtime comparison in `plugins/sp/scripts/script-contract-check.ts` Rule 1 with a regenerate-and-compare check using the pinned `superskill script convert` (byte-deterministic, verified 2026-09-25); tests in `plugins/sp/tests/script-contract-check.test.ts`.
- Out: changing the twin build tool or `build:scripts`; the manifest format; non-standard (internal) scripts; the other script-contract rules.

## Acceptance Criteria

```gherkin
Feature: Content-verified standard-script twins

  Scenario: R1 — Stale twin with a newer mtime is caught
    Given a standard script whose .mjs twin was built from an older .ts and whose twin mtime is newer than the source
    When script-contract-check runs
    Then it reports a stale_twin violation for that script and exits non-zero

  Scenario: R2 — Fresh twin with an older mtime passes
    Given a standard script whose .mjs twin is byte-identical to a fresh convert of its .ts and whose twin mtime is older than the source
    When script-contract-check runs
    Then no stale_twin violation is reported for that script

  Scenario: R3 — Missing converter fails loudly
    Given the superskill converter cannot be resolved
    When script-contract-check runs
    Then it reports a converter-unavailable violation and exits non-zero instead of silently skipping the content check
```
