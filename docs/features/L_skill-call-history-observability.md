# L: Skill-call history observability

## Goal
Make agent skill-load behavior a first-class, queryable signal in the history pipeline: a normalized `history_skill_call` table (mirroring `history_tool_call`), per-agent extraction during LLM-conversation history import, and a skill-load breakdown on the History module Summary tab backed by a materialized rollup — enabling skill trigger/usage analytics (which skills fire, on which agents, user- vs model-invoked, and fire-rate trends) across the supported coding agents.
## Scope
- In:
  - `history_skill_call` derived table + domain types (0735)
  - Per-agent skill-load extraction during `spur history import` for claude, pi, omp, codex, agy, gemini, grok, opencode, openclaw (0736)
  - History Summary tab skill-load breakdown + `history_skill_rollup` materialization (0737)
- Out:
  - Skill quality/trigger evaluation or authoring (future, downstream of this data)
  - Changes to existing `history_message` / `history_tool_call` semantics
## Acceptance Criteria
- AC1: `history_skill_call` is created by the history schema and populated during import for every supported source with a documented per-agent signature.
- AC2: A skill load is recorded with its canonical skill name, invocation kind (user/model), resolved SKILL.md path when available, and invocation args; prose that merely quotes a wrapper produces no row.
- AC3: The History Summary tab shows per-skill / per-agent / per-invocation-kind counts and a trend, served from a materialized rollup so windowed queries do not scan the detail table.
- AC4: Each task's acceptance criteria pass (`spur task check 0735|0736|0737` green), with no regression in existing history import or Summary KPIs.
