# B61: Usage availability decision correctness and bounded capture

## Goal

Make the existing run-once usage refresh conservative, truthful and bounded after I31/0904 exposed decision/reporting defects and an unbounded Codexbar capture.

## Scope

In: skip providers without named-window signal; preserve operator ownership in preview and apply; reconcile producer output against its exact durable observation; cap capture with the existing runtime timeout; isolated regression tests and the owning session-pinned-dispatch design contract.

Out: new CLI nouns/verbs/options, new scheduler, automatic live refresh, new quota thresholds, freshness admission policy, extraRateWindows decisions, global executor reconfiguration, changing delivery-ack counters into byte-mutation counters, and a new availability writer.

## Acceptance Criteria

```gherkin
Feature: Make the existing run-once usage refresh conservative, truthful and bounded after I31/0904 exposed decision/reporting defects and an unbounded Codexbar capture.

  @core
  Scenario: R1 — usage decisions require a real signal and respect operator ownership
    Given a provider has no named-window signal or an executor is operator-disabled
    When usage is previewed and applied
    Then no signal causes no availability observation and operator ownership is preserved in both modes

  @core
  Scenario: R2 — usage actions describe acknowledged outcomes
    Given a usage observation is recorded, skipped, superseded or fails during drain
    When the command returns its change rows
    Then applied requires that exact observation to be acknowledged without a skip and pending or skipped outcomes never claim applied

  @core
  Scenario: R3 — Codexbar capture has a finite deadline
    Given a Codexbar process hangs or returns partial stdout before hanging
    When the capture deadline expires
    Then capture fails closed after runtime-owned process cleanup without snapshot, observation or configuration writes

  @core
  Scenario: R4 — usable partial provider results remain supported
    Given Codexbar exits normally with nonzero status and a parsable provider array
    When usage refresh processes the capture
    Then healthy provider entries are evaluated and provider errors remain isolated
```
