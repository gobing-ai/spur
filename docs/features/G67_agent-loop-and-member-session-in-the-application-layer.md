# G67: Agent loop and member session in the application layer

## Goal

The self-draining agent loop and its G66 member session live in `packages/app`, and `spur agent loop` becomes a
thin transport over them (ADR-021). Today about 700 lines of orchestration sit in
`apps/cli/src/commands/agent.ts`: the member session (`:973-1195`: mode resolution, persistent process,
reset and resume bookkeeping) and the loop (`:1196-1728`: wake-then-drain, orchestrator ownership and dispatch,
idle holds, the failed-drain budget). No other transport can reuse it, and it can only be tested through a
`CliContext`.

Source: `/sp:dev-review apps --focus all` (2026-09-25), architecture candidate C1 (wrong seam / poor test
surface); base commit `872024cd2`. Behavior-preserving refactor: G66 and 0831/0834/0839 contracts are unchanged.

## Scope

- In: new `packages/app/src/services/member-session.ts` and `agent-loop-service.ts`; the matching sections
  of `apps/cli/src/commands/agent.ts` shrink to wiring; `packages/app/src/index.ts` exports; existing loop
  tests re-pointed and new package-level unit tests.
- Out: any `spur agent` flag, output line, exit code or ledger event name; `runAgentRun`, `runAgentWait`, the
  usage producer; `AgentService`, `FleetService`, `StrategyRuntime`, `DeliveryReconciler` internals; the
  `@gobing-ai/ts-ai-runner` package; server or web adoption of the loop (a later feature).
