# F5: Execution pipeline

## Goal

The work pipeline that gets one task done — `config/workflows/task-pipeline.yaml` run by the
existing engine, with HITL continue. Orchestration is configuration, not code (design §6).

## Scope

task-pipeline.yaml (precheck → implement → test → review → approve → verify → record),
`spur workflow continue [run-id] [--yes]`, run linkage. **Out:** the sp skill that drives it (H1).

## Acceptance Criteria

```gherkin
Feature: Execution pipeline

  Scenario: The pipeline never touches files directly
    Given a pipeline run reaching its record step
    When results are written to ## Testing and ## Review
    Then the writes go through spur task update --section
    And status transitions go through the normal verb with lifecycle guards applied

  Scenario: Pre-gate blocks unready tasks
    Given a task failing spur task check hard-core rules
    When the pipeline starts
    Then the precheck guard fails the run before implement

  Scenario: HITL continue resumes the latest pause
    Given one paused pipeline run
    When spur workflow continue --yes runs without a run-id
    Then the latest paused run is discovered and resumed
```
