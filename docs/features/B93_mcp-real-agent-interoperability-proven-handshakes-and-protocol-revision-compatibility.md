# B93: MCP real-agent interoperability: proven handshakes and protocol-revision compatibility

## Goal

Replace the documentation-based MCP adoption verdicts with evidence. Each supported coding agent either completes a real MCP handshake and tool call against `spur serve`, or has a recorded, root-caused failure and a working fallback. The server's protocol-revision policy becomes a stated contract instead of an unverified assumption.

## Scope

- In:
  - A real-agent interop harness: for each agent that is installed, configure it against a live `spur serve` MCP endpoint (HTTP and stdio bridge), run one `tools/list` and one read-only `tools/call`, and record the protocol revision the client sent and the outcome.
  - Root-cause the Codex HTTP case (it configures cleanly but reports no tools). Fix it on the server if the server is at fault; otherwise record the client limitation and prove the stdio-bridge fallback works.
  - Protocol-revision policy: decide in an ADR-152 amendment between a supported revision range and a clear version error that names the accepted revision. Implement and test the chosen behavior.
  - Update `docs/design/mcp-agent-adoption.md` verdicts from the receipt only.
- Out:
  - Installing agents that are missing on the machine: a missing agent is recorded as `not-installed`, not as a failure.
  - New MCP tools, resources, or the Board's display of these verdicts.
  - Per-client authentication identity (still one shared bearer token).
