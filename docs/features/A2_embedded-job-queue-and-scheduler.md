# A2: Embedded job queue and scheduler

## Goal
`spur serve` executes asynchronous work through the embedded DB-backed job queue and cron scheduler on the Bun path — a polling worker loop with a typed handler registry and scheduler lifecycle wired into server startup/shutdown.
## Scope
- In:
    - Enable the queue on the Bun serve path: `jobQueueEnabled` on (`apps/server/src/context.ts:138` currently defaults false) and `scheduler.enabled` on (`apps/server/src/bootstrap.ts:36` currently false).
    - Worker: polling consumer loop over the existing `DBJobQueue`/`QueueJobDao` (`queue_jobs` table) with graceful shutdown — in-flight job completes or is released, never orphaned.
    - Typed job handler registry in `packages/app` (job kind → handler); unknown kinds fail loud.
    - Scheduler start/stop wired into the serve lifecycle (`NodeSchedulerAdapter` already constructed in `ServerContext`).
    - First consumers: `system_events` retention pruning (feature J) as the first scheduled job; one smoke/no-op job kind for tests.
    - Job lifecycle events emitted on the EventBus (enqueued/started/completed/failed) so the Observability module can display them.
    - Read surface: `GET /api/jobs/stats` (counts by status) + Jobs tab added to the board Observability module (feature J owns the module shell).
- Out:
    - Cloudflare Workers execution — CF keeps the `NotConfiguredError` stance (D1 not configured).
    - A separate worker process or `--worker` flag.
    - Retry/backoff/priority sophistication beyond what ts-infra `JobQueue` already provides.
## Acceptance Criteria
```gherkin
Feature: Embedded job queue and scheduler

  Scenario: Worker executes an enqueued job
    Given spur serve is running on Bun with the queue enabled
    When a job with a registered handler kind is enqueued
    Then the handler executes and the queue_jobs row reaches a terminal completed status

  Scenario: Unknown job kind fails loud
    Given a job whose kind has no registered handler
    When the worker claims it
    Then the job is marked failed with an error message naming the unknown kind

  Scenario: Scheduler fires a registered cron entry
    Given spur serve is running with the scheduler enabled
    When a registered cron entry elapses
    Then the scheduled action runs and a corresponding job event is observable on the EventBus

  Scenario: Graceful shutdown never orphans a claimed job
    Given a worker with a job in flight
    When the server receives a shutdown signal
    Then the worker loop stops and the in-flight job is completed or released back to pending

  Scenario: Cloudflare entrypoint is unaffected
    Given the Cloudflare Workers entrypoint
    When the worker boots
    Then no queue or scheduler starts and health plus OpenAPI endpoints still serve

  Scenario: Job stats are readable over the API
    Given jobs exist in multiple statuses
    When GET /api/jobs/stats is requested
    Then counts per status are returned

  Scenario: Jobs tab shows queue activity on the board
    Given the board Observability module is open
    When the operator opens the Jobs tab
    Then job counts and recent job events render
```
