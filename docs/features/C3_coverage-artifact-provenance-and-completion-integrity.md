# C3: Coverage artifact provenance and completion integrity

## Goal

Make the repository post-test coverage gate consume only a completed canonical full-suite artifact bound to the tested working tree, with an explicit provenance failure for incomplete or stale evidence.

## Scope

In: scripts/commands/run-tests.ts, a repository coverage-artifact-check command, canonical root test entrypoints, test-post-check entrypoints, coverage rule producer documentation and regression fixtures. Out: test hang diagnosis, threshold relaxation, LCOV parser replacement, portable rule-engine API changes, extra full-suite executions.

### Approved follow-up — 2026-11-05

W8 / R8: native TOML parsing for coverage diagnostic thresholds, preserving canonical coverage provenance, missing-setting behavior and Bun enforcement. This extends diagnostics only and does not replace LCOV or lower a floor.

## Acceptance Criteria

```gherkin
Feature: C3
Scenario: Interrupted and targeted evidence cannot become file verdicts
  Given bounded producers that exit nonzero, are interrupted, or run only a targeted subset
  When coverage-artifact-check and the repository post-check evaluate their artifacts
  Then they fail with a provenance diagnostic before the coverage rule runs
Scenario: Certified evidence retains real threshold failures
  Given a certified fixture whose production file has 89 percent line coverage
  When provenance validation passes and the real existing coverage evaluator reads it
  Then the evaluator reports its original below-threshold finding
  And an otherwise identical 90 percent fixture passes
Scenario: Tree and artifact identity are enforced
  Given a successful canonical fixture producer
  When source changes during or after its run, LCOV bytes change, or a marker is malformed or missing
  Then certification or post-check refuses the evidence
Scenario: Concurrent publication is fail closed and bounded
  Given two controlled canonical fixture producers with distinct run ids
  When the earlier producer finishes after a later producer starts
  Then the earlier producer cannot publish certification over the later run
  And each canonical command launches exactly one suite child
Scenario: Recovery and caller scope are documented
  Given root package.json and config/rules/quality/coverage-gate.yaml
  When the entrypoints and producer note are inspected
  Then both repository post-check variants validate provenance first
  And a completed successful canonical full run is the documented recovery
  And direct portable spur rule execution is documented as outside this repository certification wrapper

  @core
  Scenario: R6 — Equivalent TOML threshold forms produce equivalent diagnostics
    Given inline and standard-table forms of the same coverage threshold plus absent and malformed settings
    When the quality gate reads coverage diagnostics
    Then valid equivalent forms report the same shortfalls while invalid input is actionable and missing settings retain documented behavior without weakening Bun coverage enforcement
```
