# A822: Cross-project A2A sequence stitching

## Goal

When the A2A sequence view shows an outbound call to another project served by the same local
gateway, the operator can expand that arrow and read the remote project's own dialog for the
call, instead of a dead end at the project boundary. Follow-up to A821 (`docs/design/integrations-module.md` §3.1).

## Scope

- In:
  - A read-only resolver that maps an outbound receipt's target URL to a project registered on the
    same gateway (gateway path prefix + projects registry) and reads that project's
    `inbox.thread({ id: remoteTaskId })` through the gateway. The remote A2A task id equals the
    remote inbox message id (`apps/server/src/modules/a2a/index.ts:218`, `:326`); the local receipt
    already stores `remoteTaskId` (`packages/app/src/services/a2a-member-transport.ts:80-100`).
  - Rendering the stitched remote dialog under the outbound arrow in the A2A sequence view
    (`apps/web/src/modules/integrations/A2aSequence.tsx`), with a "remote dialog not observable"
    marker for peers that are not on this gateway or whose read fails.
- Out:
  - Peers on other machines or behind other gateways (no cross-host reads, no new credentials).
  - Schema changes, new A2A protocol fields, or writes to the remote project.
  - New public `spur` nouns or verbs.

## Acceptance Criteria

```gherkin
Feature: Cross-project A2A sequence stitching

  @core
  Scenario: R1 — An outbound call to a same-gateway project shows the remote dialog
    Given project A sent an A2A message to project B and both are served by one local gateway
    And A's outbound receipt records B's remote task id
    When the operator opens A's A2A sequence and expands that arrow
    Then B's inbox thread for that task is rendered under the arrow in order

  @core
  Scenario: R2 — A peer outside the gateway is marked, not guessed
    Given an outbound receipt whose target is not a project on this gateway
    When the sequence is rendered
    Then the arrow carries a remote-dialog-not-observable marker
    And no request leaves the local gateway

  @core
  Scenario: R3 — A failed remote read degrades to the marker
    Given a same-gateway target project that is stopped or returns an error
    When the operator expands the arrow
    Then the marker names the failure and the local sequence still renders
```
