# I12: dev-idea robustness: verbatim idea artifact, requirement inventory and coverage gate, checker-aware stage prompts, --from-file

## Goal

`/sp:dev-idea` keeps every explicit ask of a long or complex idea draft from intake to task batch: the operator's text is a durable run artifact, discovery enumerates the asks, acceptance criteria are measured against that inventory, and stage prompts carry the deterministic checker rules so a cheaper model passes on the first attempt.

## Scope

In scope:
- Verbatim `.spur/run/<runId>-idea-input.md` written before discovery by both the headless `start` state and the inline driver; every model-bearing stage prompt references it.
- `## Requirement inventory` (`I<n>` items with source fragments, optional `deferred`) in the idea-evaluation report; `covers:` mapping in AC; a deterministic coverage `command.gate` routed through the existing ac-generate retry loop.
- ac-generate / decompose / feature-create prompts state the L4 task-check rules and the `create --json` envelope.
- `--from-file <path>` on `/sp:dev-idea` (plugin command flag; glossary + § idea updated).
- Inline `--action` trace rows back-date `startedAt` by `durationMs`.
- `build:bundle`, contract-baseline refresh, parity/validate-commands/plugin tests.

Out of scope:
- `--auto` / taste-gate semantics, pipeline state nesting or splitting, public `spur` noun/verb additions, per-task Design content rules.

  When the coverage gate runs under profile=auto

  And the run-scoped status file names the uncovered item

Scenario: R4 — Stage prompts carry the checker rules and the create envelope
  Given the ac-generate, decompose and feature-create prompts
  When a run creates tasks from a fresh idea
  Then the created tasks pass spur task check with zero L4 gate-language or uncovered-scenario findings on the first pass
  And the feature id is read from .ref.id without correction

  And the flag is documented in the flag glossary and dev-operations § idea

  Given an inline --action record with --duration-ms 120000
  When spur workflow trace --json renders it
  Then completedAt minus startedAt equals 120000 ms

  Given the idea-pipeline.yaml change
