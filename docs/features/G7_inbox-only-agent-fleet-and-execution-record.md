# G7: Inbox-only agent fleet and execution record

## Goal

The agent fleet works the way ADR-057 promises: every agent↔agent and operator↔orchestrator exchange goes through the inbox, members execute their own work, completion is a durable receipt, and every execution leaves a durable, restart-proof record (ADR-132). Team-era residue is gone, and a live interactive session can cooperate with the fleet without terminal injection.

Plan: `docs/plans/2026-10-04-agent-fleet-inbox-redesign.md`. ADR changes landed first (ADR-057, 086, 121, 126 amendments; new ADR-132).

## Scope

- In: G71 core inbox fleet (dispatcher, member execution, resume, identity, execution record, E2E receipt); G72 team-residue cleanup (code, contracts/web, instance store, docs); G73 cooperative participation (hook-reported lifecycle, guest join, Codex parity spike).
- Out: herdr PTY transport, PID-attach, ACP/UHP executors (rejected, plan §2.4); adjacent findings A1–A5 (separate tasks); upstream ts-ai-runner renames.

## Acceptance Criteria

```gherkin
Feature: Inbox-only agent fleet and execution record

  Scenario: R1 — The fleet runs work only through the inbox
    Given a project with agent.fleet enabled and a fleet:auto todo task
    When the orchestrator dispatches it

    Given the repository after G72
    When code, contracts, web and docs are searched for team-era residue
    Then no teamId field, TeamOrchestrator use, agent_instances table or team-mode design link remains
```
