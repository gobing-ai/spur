# D5: task-pipeline2 promotion gated by the eval-suite bar

## Goal
Promote `config/workflows/task-pipeline2.yaml` over the live `task-pipeline.yaml`
only when the eval-suite bar says so: verdict parity, gate integrity, and a clean
exit-0 comparator run against the 0595 fixture set.
## Scope
- In:
    - Keep `task-pipeline2.yaml` as a **parallel** file beside the live pipeline
      until promotion (I6 standing rule; 0596). The live `task-pipeline.yaml` is
      unmodified until the bar passes.
    - The `residual-sweep` FSM stage stays after `verify` PASS and before
      `record` / commit (`task-pipeline2.yaml` residual-sweep stage).
    - The `scripts/spur-dev.ts eval-pipeline` comparator (0595) is the promotion
      gate, not operator inspection.
    - The proposed bar, pending operator ratification of map open question 1:
      verdict parity PASS=PASS, gate integrity, wall-clock within +10 % of the
      0595 baseline (538s), and a **clean exit-0** run (0596's parity run was
      PASS on verdict but not clean-exit because of executor-quota interference).
    - Forward `residualSweepTarget` from the batch driver for `--feature` batches
      (0596 P3 follow-up — one `--vars` add).
- Out:
    - In-place edits to the live `task-pipeline.yaml` before the bar passes.
    - Declaring per-stage model/executor tiers in the YAML (I6 fog; not yet
      expressible as a decided approach).
    - New `spur` CLI nouns or verbs (ADR-051).
    - Replacing the inline two-layer plan renderer
      (`plugins/sp/skills/spur-dev/references/inline-pipeline-driver.md`).
