# I61: Tool-usage feedback loop: protocol events into history-anatomy, doctor and rule-scan

## Goal

Turn protocol and command usage events into decisions: per-tool call counts, failure rates and latency in the daily history-anatomy report, unused or failing surfaces flagged by spur-doctor, and repeated identical failures proposed as rules.

## Scope

**In scope**
- Forensics artifact `protocolUsage` cited in history-anatomy section 8 (frozen 12 sections): per-tool counts, failure rate and p95 from mcp.* events; per-actor counts; a2a counts per member and outcome.
- history-anatomy findings for high-failure tools and zero-use commands/skills (E93 usage + plugin inventory), routed by the existing spur-doctor reflection map; MCP tool zero-use is a telemetry gap until descriptors are package-importable.
- rule-scan event-evidence source: repeated (tool, errorCode) clusters from the artifact as candidates, with a `not-a-rule` route.

**Out of scope**
- Automatic deletion or rule activation (operator approves).
- New telemetry storage beyond system_events and the history plane.

## Acceptance Criteria

```gherkin
Feature: Tool-usage feedback loop: protocol events into history-anatomy, doctor and rule-scan

  @core
  Scenario: R1 — Daily report shows protocol tool usage
    Given a window with mcp and a2a events

    Then the report lists per-tool and per-agent counts, failure rate and p95 duration

  @edge
  Scenario: R3 — Repeated tool failures become rule candidates
    Given the same tool failing with the same error code repeatedly
    When rule-scan runs
    Then it proposes a candidate rule citing the event evidence, not activated until approved

```
