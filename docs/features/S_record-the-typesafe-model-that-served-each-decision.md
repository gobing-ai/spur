# S: Record the TypeSafe model that served each decision

## Goal

Every `decision_logs` row for the hosted `typesafe` maker records the model TypeSafe actually served, so a `TYPESAFE_DEFAULT_MODEL` pin (or the `jev-latest` fallback) can be audited after the fact. Follow-up deferred from task 1436 (Q&A).

## Scope

- In: a ts-libs `@gobing-ai/ts-ai-decision` answer-metadata API that surfaces `SystemOneResult.model` (the typesafe driver drops it by design today, ts-libs task 0072 R8); a `decision_logs` column plus migration that stores it; `spur decision` output showing it.
- Out: changing how the model is selected (stays the SDK's `TYPESAFE_DEFAULT_MODEL` env var, task 1436 R6); per-call model selection through catalog `model:` fields.

## Acceptance Criteria

```gherkin
Feature: Record the TypeSafe model that served each decision

  Scenario: R1 — the served model is logged per decision
    Given the `typesafe` maker answers a decision
    When the decision is logged
    Then its `decision_logs` row carries the model name TypeSafe reported serving

  Scenario: R2 — non-typesafe makers leave the served model empty
    Given a maker that reports no served model
    When the decision is logged
    Then the served-model column is null and nothing else changes
```
