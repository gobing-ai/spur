# F1: Planning foundation

## Goal

The W0 substrate everything else builds on: Zod frontmatter schemas (the parse-validate-serialize
SSOT), the unified markdown I/O module, the shared BDD validator, the lock domain, and
cross-cutting consolidation on ts-utils/ts-runtime — per design §2–§4 and DD-01…DD-10.

## Scope

`packages/domain` modules only (schemas, MarkdownDocument, bdd, locks) + test helpers + upstream
consolidation audit. **Out:** services, CLI verbs (F2/F3), lifecycle wiring (F4).

## Acceptance Criteria

```gherkin
Feature: Planning foundation

  Scenario: Frontmatter schemas are the single source of truth
    Given a task file with valid frontmatter
    When it is parsed and re-serialized through the domain schemas
    Then the result is byte-identical for untouched content
    And invalid frontmatter fails with field-level Zod errors

  Scenario: Status vocabulary is canonical and tolerant
    Given the input status "Completed"
    When it is normalized
    Then the stored value is "done"
    And unknown statuses are rejected with the allowed set listed

  Scenario: BDD validator gates acceptance criteria
    Given a feature file with a malformed Gherkin scenario
    When validateAcceptanceCriteria runs
    Then a line-numbered issue is reported
    And a well-formed two-tier AC passes with zero issues

  Scenario: Concurrent creation is race-safe
    Given two concurrent create operations in one folder
    When both request a new WBS under the create-lock
    Then they receive distinct sequential numbers
    And no lock remains after both complete
```
