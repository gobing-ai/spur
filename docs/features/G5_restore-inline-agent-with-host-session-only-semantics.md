# G5: Restore inline --agent with host-session-only semantics

## Goal
Restore `inline` as a valid `--agent` value meaning host-session-only execution: slash commands and their backend agent skills must never dispatch prompts or work to any other session (no subagents, subprocesses, or workflow hops), while headless `spur` CLI surfaces that cannot host a session respond to `--agent inline` with a stable, explicit error and take no further action.
## Scope
**In scope**

- Add `inline` back as a closed value in the unified `--agent <inline|auto|name>` table (ADR-047), with host-session-only semantics.
- Slash commands and backend agent skills: explicit `inline` MUST execute all model-bearing work in the invoking host session — no subagent, subprocess, or workflow hop — regardless of ADR-047/0508 native-subagent eligibility.
- Headless surfaces (`spur agent run`, workflow `agent.run`, serve-side dispatch): `--agent inline` returns a stable, greppable special error and performs no further action — no dispatch, no `agent.default` fallback.
- `omit`, `auto`, and named selectors keep current behavior unchanged.
- Update consumers that currently document or rely on `inline` resolving to `agent.default` (agent-service resolution, workflow agent-run action, dev-plan docs) in the same change.
- T3 doc sync: ADR-047 amendment, flag glossary, `docs/04_DESIGN.md` §7.8, cross-cutting inline-default contract.
- Tests at CLI, service, and workflow-action layers.

**Out of scope**

- Changing `omit` behavior or removing 0508 native-subagent eligibility for `omit`/`auto`/named selectors.
- Enforcing the host-session guarantee by mechanism inside skills (convention only; CLI error covers subprocess dispatch).
- New flags, config knobs, or env gates for the inline behavior.
- Any data, schema, or migration impact.
