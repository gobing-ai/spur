# B92: MCP as the primary agent interface: guarded corpus write tools and adoption

## Goal

Make typed MCP tools the default way coding agents read and change the Spur corpus, with the CLI as fallback, so the "CLI-gated corpus writes" and "never invent flags" rules are enforced by tool schemas instead of prompt prose.

## Scope

**In scope**
- Write tools `sp_task_create`, `sp_task_update`, `sp_task_transition`, `sp_feature_check`, `sp_rule_run` delegating to the same app services and guards as the CLI (transport parity, F41 pattern). Status changes go only through `sp_task_transition`. Operator overrides (`forceDone`), arbitrary rule files, `fixMode: auto` and model-backed ready-prep stay CLI-only.
- Per-agent MCP adoption matrix for the ten supported agents (Streamable HTTP and stdio-via-`spur mcp` support at protocol 2026-07-28, each cited or UNVERIFIED), recorded in `docs/design/mcp-agent-adoption.md`.
- MCP-first guidance with CLI fallback in `sp:spur-dev`, `sp:spur-cli` and AGENTS.md as one runtime rule (use `sp_*` tools when present, otherwise the CLI) with no per-agent branching.

**Out of scope**
- Removing CLI verbs.
- Superskill-side install changes (requested through cross-project delegation or a superskill task).

## Acceptance Criteria

```gherkin
Feature: MCP as the primary agent interface: guarded corpus write tools and adoption

  @core
  Scenario: R1 — Corpus write tools delegate to the guarded services
    Given an authenticated MCP client
    When it calls sp_task_create, sp_task_update, sp_task_transition, sp_feature_check or sp_rule_run
    Then each call runs the same application service as the CLI verb and returns its result

  @core
  Scenario: R2 — Guards refuse identically on MCP and CLI
    Given a transition the lifecycle guard refuses (for example done without a PASS verdict)
    When it is attempted through the MCP tool and through the CLI
    Then both refuse with the same code and message and write nothing

  @core
  Scenario: R3 — Adoption matrix records verified MCP support per agent
    Given the ten supported coding agents
    When the adoption matrix is produced
    Then each agent row states stateless MCP 2.0+ support with a cited source or UNVERIFIED

  @edge
  Scenario: R4 — Agent guidance prefers MCP with CLI fallback
    Given an MCP-capable agent loads sp:spur-dev or sp:spur-cli
    When it needs a corpus read or write
    Then the guidance names the sp_ tool first and the CLI verb as fallback

```
