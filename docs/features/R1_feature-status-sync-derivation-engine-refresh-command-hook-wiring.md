# R1: Feature status sync: derivation engine, refresh command, hook wiring

## Goal
Implement the feature-R map's locked decisions: a derivation engine mapping linked-task state to legal feature transitions, exposed as `spur feature sync` (CLI) and the un-stubbed Board sync endpoint; refresh hooks in the task pipeline, wrapup, and dev-verify; the `/sp:dev-refresh` operator command; and a one-time operator-confirmed backfill of the drifted corpus.
## Scope
- Derivation engine in `packages/app` feature-service + `spur feature sync` CLI verb + un-stub `POST /features/{id}/sync` (pull).
- Refresh hooks: task-pipeline record phase, wrapup feature-transition step, `/sp:dev-verify` PASS step.
- `/sp:dev-refresh` command (feature-id | wbs | `--all` | `--auto`).
- One-time operator-confirmed backfill of the drifted corpus + legacy `Done` status normalization.

Out: Board tree status icon / filter (already map tickets under R); `push` sync implementation (defined-but-deferred).
## Acceptance Criteria
R1 @core — `spur feature sync <id>` derives the target status from the feature's linked tasks using the conservative forward-only mapping (all tasks terminal ⇒ advance toward `done`, L4-gated at `verifying`; any `wip`/`testing` ⇒ `backlog→active`; all non-terminal `blocked` ⇒ `blocked`; empty set ⇒ no-op) and applies proposals via `spur feature advance` hops with reasons in `--json` output.

R2 @core — `POST /features/{id}/sync` with `direction: pull` delegates to the same service and returns `{ affectedTasks, newStatus? }`; `direction: push` returns an explicit not-implemented error.

R3 @core — task-pipeline record phase and wrapup feature-transition call `spur feature sync`; wrapup no longer advances unconditionally; unattended runs auto-apply forward-only and queue orphan link proposals to the run report.

R4 @core — `/sp:dev-refresh` supports feature-id, task-WBS (link-helper propose/confirm/skip with persisted skip when unlinked), and `--all` combined sweep with per-item confirm + summary report; `--auto` follows the unattended policy.

R5 @edge — after the backfill run, no linked done task sits under a feature still at `backlog` (`spur feature check` clean), and legacy `Done` task statuses are normalized to `done`.
