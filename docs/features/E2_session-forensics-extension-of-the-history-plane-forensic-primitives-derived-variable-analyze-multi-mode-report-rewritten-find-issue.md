# E2: Session-forensics extension of the history plane: forensic primitives, derived-variable analyze, multi-mode report, rewritten find-issue

## Goal

### Destination

One or more **implementation-ready task files** that specify how `spur history` gains omp's
session-forensics capability — forensic primitives retained at import, derived variables computed by
`analyze`, a `--mode`-selected report renderer, and a `/sp:dev-find-issue` rewritten to consume them.

The map closes when those task files exist and pass `spur task check`, not when the code lands.
Implementation is a downstream effort against the specs this map produces.

### Why this is a map and not a spec

Feature **E1** already shipped the history data plane (`import` across 10 sources with
full/incremental/force-file modes and `--source all` fan-out; `analyze` with the Q1–Q10 forensic query
set; `report` as a pure artifact renderer; `daily` as the scheduled loop). The question is not "build a
history plane" — it is **which parts of omp's forensics methodology the existing plane can already
carry, and which require schema, mapper, or contract changes**.

That answer is not knowable from reading the request. One structural gap is already visible without
investigating: `history_tool_call` stores `args_digest` (a hash), not the arguments
(`~/xprojects/ts-libs/packages/llm-jsonl-importer/src/schema-sql.ts:120`). omp's phase detection reads
**todo-event contents** to name phases, so the single most distinctive primitive in the sample report
cannot be computed from the current schema at all. How many more gaps like that exist, across ten
sources, is exactly what the frontier tickets are for.

## Scope

### In

- `spur history import` — retaining whatever forensic payload the primitives need, and the per-source
  mapper work that makes ten agents produce one comparable shape.
- `spur history analyze` — the derived-variable layer (phases, time decomposition, bottleneck ranking,
  issue candidates) on top of today's Q1–Q10 set.
- `spur history report` — `--mode` selection bound to a renderer, forensics being the first new mode.
- `spur history daily` — the `--mode` wiring only; the verb itself stays (see Decisions so far).
- `plugins/sp/commands/dev-find-issue.md` + `sp:issue-finding` — the rewrite that consumes the above.

### Out

See `### Out of scope` under `## Notes`.

### Verified during refine (2026-08-09) — corrections to the charting-session terrain

Four premises the charting session asserted were checked against the tree; two were wrong in ways
that changed a ticket.

- **The analyze-mechanism fork is three-way, not two-way.** `host.registerAction(runner, origin)` is
  a public seam (`packages/app/src/workflow/builtins.ts:44`, `:64-78`) and the workflow schema leaves
  `kind` unconstrained (`apps/cli/schemas/state-machine-workflow.schema.json:74`), so a typed
  `history.derive` action needs **no schema change**. Comparing shell-orchestration against an
  in-analyze registry alone would have tested the operator's `spur workflow` framing at its weakest.
  The eleven builtin kinds live in `packages/app/src/workflow/actions/`.
- **`/sp:dev-find-issue` is a thin wrapper, and a history bridge already exists.** The command file is
  `Skill(skill="sp:issue-finding", args="$ARGUMENTS")` plus flag tables; the substance is
  `plugins/sp/skills/issue-finding/SKILL.md` (424 lines). `--use-history` ships today, and Phase 2
  states _"Do not treat history ETL as a substitute for raw tool-loop evidence."_ The rewrite is
  therefore an **inversion of a written position**, not a new integration.
- **A second per-source field map exists.**
  `plugins/sp/skills/issue-finding/references/session-formats.md` (121 lines) holds in prose what the
  importer mappers hold in code. The coverage matrix owns the ownership verdict; the command rewrite
  owns the edit.
- **`args_digest` is load-bearing, not dead weight.** Q4 loop detection is built on it
  (`packages/domain/src/analytics/forensic-query.ts:275`), so any retention proposal is additive.

### Decisions so far

- **`spur history daily` stays and gains `--mode`** (operator, 2026-08-09) — it already exists, is the
  scheduled loop, and owns per-source failure isolation, checkpoint self-heal, and 90-day pruning.
  Re-creating that composition in a shell script is churn. It gains report-mode wiring; nothing else.
- **Report modes are built-in named renderers, not file templates** (operator, 2026-08-09) —
  `report --mode spend|forensics|…` resolves to a TS renderer over the artifact, like today's
  `renderReport`. No template engine, no variable-binding contract, no new config surface. File
  templates are deferred until a second author needs one.
- **The destination is implementation-ready task files, not landed code** (operator, 2026-08-09) — the
  map produces specs; implementation is a downstream effort.
- **Forensic-primitive coverage matrix settled** (0489, 2026-08-10) — the importer mappers (`mappers.ts`)
  are the single code authority for what the typed tables retain. `session-formats.md` reduces to the
  source→root path table and the fallback-bridge note; per-source fidelity ratings are deleted (the
  matrix owns them). Four genuine import deltas identified: custom mappers for gemini/opencode/
  antigravity/openclaw, `duration_ms` extraction, raw tool-args retention, tool-result retention.
- **Mechanism B: in-analyze metric registry** (0490, 2026-08-10) — derived variables (phases, time
  decomposition, bottleneck ranking) computed inside `spur history analyze`, surfaced as a v2 artifact
  shape. Not shell orchestration, not a separate sidecar. MEDIUM confidence (spike recommendation).
- **`report --mode forensics` renders 8 derivable sections** (0491, 2026-08-10) — mode registry
  subsumes `renderReport` + `renderMarkdown`; forensics renderer validated against a synthetic artifact
  mirroring the omp sample. 8 derivable, 2 partial, 6 model-authored. TTFT/Generation split deferred
  (artifact has no intra-call latency fields).
- **Import retention: digest + per-tool allowlist + latency** (operator ruling, 2026-08-09) —
  raw args retained for todo-writing tools only, alongside `args_digest` (phase detection,
  ~1–16 KB/session extrapolated); `duration_ms` extracted from raw JSONL (time decomposition,
  ~2.4 KB/session measured). Tool result content not retained; issue-categorization stays on the
  raw-JSONL fallback (0492 R7). Narrows 0492 R6 order-1 scope to allowlist + latency extraction.
- - **`/sp:dev-find-issue` becomes report-first** (operator ruling, R3, 0492, 2026-08-10) — default
    output is markdown report to stdout (8 derivable from CLI + 6 model-authored from skill). Task
    creation behind `--create-task`. `--use-history` and `--no-task` removed. The skill's raw-evidence
    stance is inverted, not abandoned: the data plane is primary; raw JSONL parsing is the fallback when
    (1) a source has no typed mapper, (2) `--sessions` is passed, or (3) a primitive needs content the
    typed tables do not yet retain.
