# E1: History data plane trustworthy end-to-end: forensic ETL, verified incremental import, analyze/report, one scheduled loop

## Goal
**Destination:** `spur history` import → analyze → report produces data trustworthy enough to
diagnose a real agent session, proven by one scheduled morning import→report loop and one ad-hoc
forensic query answering "which tool loop burned this session".

This is a **wayfinder map** (see `## Notes`). Investigation tickets resolve one per session; implementation
work graduates into tasks as the fog clears. The map closes only on
`/sp:dev-verifyall --feature E1 --fix all` reporting `Shippable: PASS`.
## Scope
### In

- Forensic ETL contract: tool calls, per-step durations, model, usage rollup, session/turn linkage.
- Sources at full fidelity: **claude, codex, pi, omp, agy, grok**.
- `spur history import` — full + incremental + ad-hoc (single file / single session), machine-parsable
  `--json` at real volume.
- Incremental correctness: `history_import_checkpoint` / `history_import_ledger` verified against
  real append-only growth.
- `spur history analyze` — JSON query-result artifact.
- `spur history report` — render from that artifact (currently a stub, `apps/cli/src/commands/history.ts:39`).
- One scheduled morning loop: import yesterday's sessions → analyze → report.

### Out of scope

- Source support for **gemini, opencode, antigravity-ide, openclaw, hermes** — deferred by operator
  ruling (2026-08-06); the ETL contract must leave adding them mechanical.
- Self-evolution agentics and rewiring `sp:issue-finding` / `/sp:dev-findissue` to read the DB instead
  of raw JSONL. That is the follow-on map this one makes possible.
- Board / web visualization of history analytics.
- Reconstructing the lost 0451 diagnostic report from yesterday's transcripts — a use of this
  capability, not part of building it.

### Ground truth (measured 2026-08-06, dry-run on this machine)

`spur history import --dry-run` against real history roots:

| source | files | lines scanned | records imported | yield |
| --- | --- | --- | --- | --- |
| claude | 326 | 90,411 | 826 | **0.9%** |
| codex | — | 224,055 | 2,141 | **1.0%** (221,911 validation errors) |
| pi | — | 1,476,470 | 1,023 | **0.07%** (1,311,401 parse errors) |
| gemini / opencode / antigravity / openclaw | 0 | 0 | 0 | roots match nothing |

Root cause of the ~99% loss: `ts-llm-jsonl-importer@0.4.19` maps sources through one generic flat
`sourceDefinition` requiring a top-level `content: string`. Claude Code JSONL nests everything under
`message.{model,usage,content[]}` across 9 record types (`mode`, `attachment`, `user`, `system`,
`last-prompt`, `assistant`, `file-history-snapshot`, `file-history-delta`, `ai-title`). Tool calls —
the substance of any step-forensics report — live in content blocks the mapping drops entirely.

**Already built upstream, do not rebuild:** `history_import_checkpoint(source, source_file,
last_imported_line, updated_at)` and `history_import_ledger(record_hash, source, source_file,
source_line, split_index, target_table, imported_at)` exist in `HISTORY_IMPORT_SCHEMA_SQL`, and
incremental mode reads the checkpoint (`src/importer.ts:59`). The operator's dedupe requirement is a
**verification** question, not a build.

**Wiring that already works:** `spur history import|analyze` are wired end-to-end
(`apps/cli/src/commands/history.ts:10`, `packages/app/src/services/history-service.ts:45`). `report`
is an explicit not-implemented stub. Root resolution is correct (registry `defaultRoots` are
home-relative, `src/importer.ts:231`).

**Two drifted registries.** `@gobing-ai/ts-ai-runner` `src/agents/shims.ts` is the canonical agent
roster — `claude`, `codex`, `gemini`, `pi`, `opencode`, `antigravity-cli` (command `agy`, alias
`antigravity`), `openclaw`, `hermes`, `omp`, `grok`. The importer's `LlmJsonlSource` union is a
separate hand-maintained list — pi, claude, codex, gemini, opencode, antigravity, openclaw — missing
**omp, grok, hermes** and naming antigravity differently. The source list should derive from the shim
roster rather than being maintained twice. (`agy` = `antigravity-cli`, confirmed at `shims.ts:198`.)

**Two ingestion paths, not one.** `packages/app/src/workflow/actions/agent-run.ts:143` routes
Spur-launched agent sessions into `.spur/run/<runId>/agent-sessions/<agent>/`, and
`discoverSessionId()` (`:408`) reads the session id back. For those runs the transcript path is
deterministic and already correlated to a `runId` — exact attribution, unlike the heuristic
`matchEtlPayloads` in `packages/domain/src/analytics/run-cost.ts:131`. But only **pi and omp** honor
`--session-dir` (`shims.ts:167,266`); claude, codex, agy, and grok ignore it and write to their
global `$HOME` locations. Ticket 0462 decides how the two paths combine.

**Where transcripts actually live** (measured; note every agent dir under `$HOME` is a symlink into
`~/tools/dot_files/config/`, so any probe must follow symlinks — `find -L`, not `find`):

| source | layout | `.jsonl` count |
| --- | --- | --- |
| claude | `~/.claude/projects/<slug>/<uuid>.jsonl` | 358 |
| codex | `~/.codex/sessions/…` | 1,336 |
| pi | `~/.pi/agent/sessions/--<slug>--/*.jsonl` | 1,237 |
| omp | `~/.omp/agent/sessions/<slug>/<ts>_<uuid>/*.jsonl` | 691 |
| grok | `~/.grok/sessions/<url-encoded-cwd>/<uuid>/*.jsonl` | 418 |
| agy | `~/.gemini/antigravity-cli/brain/<uuid>/.system_generated/logs/transcript{,_full}.jsonl` | 147 |

agy also keeps `~/.gemini/antigravity-cli/conversations/<uuid>.db` — 80 SQLite databases keyed by the
same session UUIDs, so it has both a JSONL and a structured store. It is **not** under `~/.antigravity*`
(operator correction, 2026-08-06); those dirs hold no transcripts.

This explains pi's 1.3M parse errors outright: its `defaultRoots` are `['.pi/history', '.pi']`,
`.pi/history` does not exist, so the walk falls back to all of `~/.pi` and matches 3,843 stray
`*.json` files that were never transcripts. The correct root is `.pi/agent/sessions`.

### Known defects to graduate (not investigations — fold into implementation tasks)

- `--json` is unusable at real volume: `validationErrors` is an unbounded array, so 221k errors
  serialize into one blob and `--json` returned nothing for pi/codex. Any scheduled loop parses
  `--json`, so this blocks the loop.
- pi's `defaultRoots` point at a non-existent `.pi/history`, falling back to the whole `~/.pi` tree
  where the `*.json` pattern matches 3,843 non-transcript files. Correct root: `.pi/agent/sessions`.
- `spur history import` takes one `--source` at a time with default `pi`; a morning loop over six
  agents needs either `--source all` or six invocations.
- No ad-hoc selector for a single session (`--file` only, no `--session <id>`).

### Decisions so far

- **2026-08-06 charting — destination scope.** Map stops at a trustworthy data plane plus one live
  scheduled loop; self-evolution agentics are a follow-on map.
- **2026-08-06 charting — source parity.** claude, codex, pi, omp, agy, grok in scope; gemini,
  opencode, antigravity-ide, openclaw, hermes deferred.
- **2026-08-06 charting — fidelity target.** Full step forensics (tool calls, per-step durations,
  model, usage rollup, session/turn linkage), not token/cost rollup and not raw passthrough.
- **2026-08-06 charting — fix placement policy.** Operator ruling: upstream `@gobing-ai/ts-*`
  packages under `~/xprojects/ts-libs` are **in scope to modify**, developed against Spur via
  `bun link`. This covers both `ts-llm-jsonl-importer` and `ts-ai-runner`. Prefer fixing the facade
  over a Spur-side workaround (`AGENTS.md`). Still open, and owned by 0459: whether the declarative
  `SourceDefinition` model can *express* step forensics, or needs a transform hook.
- **2026-08-06 charting — agent identity.** `agy` is `antigravity-cli` (`shims.ts:198`), distinct
  from the deferred antigravity-ide. Its history lives under `~/.gemini/antigravity-cli/`, not
  `~/.antigravity*` (operator correction).
- **2026-08-06 charting — ticket granularity.** Operator ruling: the first 8-ticket cut was
  over-sliced. Prefer fewer, larger tickets; a ticket is a session's work, not a single question.
