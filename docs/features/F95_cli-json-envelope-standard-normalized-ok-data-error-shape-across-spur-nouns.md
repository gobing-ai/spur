# F95: CLI JSON envelope standard: normalized ok-data-error shape across spur nouns

## Goal

Standardize the `--json` output envelope across spur nouns. Three times in the 0688 session
(2026-08-27), inconsistent shapes broke jq consumers:

- `task update`'s `.ok` is `null` where callers expect a boolean;
- `feature check --json` returns a bare array with no envelope;
- `task check --corpus --json` returns flat top-level keys with no `.summary`.

Every consumer script and every new noun surface re-learns the shape per verb today. This is an
ADR-grade, cross-cutting decision: it touches the public CLI surface of every noun, so per the
ADR-051 amendment implementation requires explicit operator consent. The feature therefore files as
**ADR proposal + shape inventory first**, with implementation gated on the approved decision.

## Scope

**In:** one dated ADR entry in `docs/00_ADR.md` proposing the normalized `{ok, data, error}`
envelope across nouns with a compat/deprecation story; a survey and inventory of current per-noun
`--json` shapes recorded as a `docs/04_DESIGN.md` section; implementation behind the ADR decision.

**Out:** any implementation before ADR approval (operator consent gate — ADR-051 amendment, public
CLI surface change). Per-noun behavior changes beyond the envelope shape. Docs-only prose
reformatting beyond the inventory section.
