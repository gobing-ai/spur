# B9: Embedded MCP 2.0+ server in spur serve

## Goal

Embed a stateless MCP 2.0+ (`2026-07-28`+ specification) server directly inside each project's `spur serve` process (`mcpModule`), exposing Spur's harness tools and indexed context resources over unified Streamable HTTP (`/mcp`, proxied at `/<prefix>/mcp` via the gateway). Coding agents interact with Spur in-process without CLI startup overhead, while avoiding legacy stateful MCP versions, `initialize` handshakes, and dual-endpoint HTTP+SSE sessions.

## Scope

**In scope**

- Stateless MCP 2.0+ (`2026-07-28`+ specification) Streamable HTTP endpoint (`POST /mcp`) returning JSON or request-scoped SSE, supporting `server/discover` and `Mcp-Protocol-Version` / `Mcp-Method` / `Mcp-Name` headers, and explicitly rejecting legacy pre-2.0 protocol versions.
- Embedded `mcpModule` registered in `apps/server/src/modules/registry.ts` (parallel to `a2aModule`), gated by `server.mcp.enabled` (default `false`) and bearer-token auth (`server.mcp.authEnv`).
- Gateway support: exempt bearer-authenticated `/<prefix>/mcp` requests from browser-origin CSRF checks in `gatewayGuard` (`packages/app/src/services/project-gateway.ts`).
- Core harness tools (`task_show`, `task_list`, `workflow_status`, `workflow_run`, `workflow_continue`) and resources (`spur://tasks/{wbs}`, `spur://features/{id}`, `spur://context/{name}`) delegating directly to `@gobing-ai/spur-app`.
- Thin `spur mcp` stdio-to-HTTP bridge for local CLI clients that only speak stdio, forwarding to `/mcp` without duplicating server logic.

**Out of scope**

- Legacy MCP protocol versions (`2024-11-05`, `2025-03-26`, `2025-11-25`), dual-endpoint HTTP+SSE transport, `initialize` handshakes, or server-side sticky sessions.
- Moving workflow orchestration out of `config/workflows/task-pipeline.yaml` and `packages/app/src/workflow/`.

  Scenario: R2 — Stateless MCP 2.0+ Streamable HTTP rejects legacy protocol versions

    Then the server responds without requiring an initialize handshake or session ID, using JSON or request-scoped SSE
    When a client requests a legacy pre-2.0 protocol version
    Then the server rejects the request with a clear protocol-version error

  @core
  Scenario: R3 — Harness tools and resources delegate to @gobing-ai/spur-app
    Given an authenticated MCP 2.0+ client
    When it invokes task_show, task_list, workflow_status, workflow_run, or workflow_continue, or reads spur:// resources
    Then each call delegates to @gobing-ai/spur-app services without introducing a second orchestration FSM

  @core
  Scenario: R4 — Gateway proxies /<prefix>/mcp with bearer-auth CSRF exemption
    Given a running gateway and a registered local project with server.mcp.enabled true
    When a client sends POST /<prefix>/mcp with an Authorization Bearer header
    Then gatewayGuard permits the request and proxies it to the project's spur serve /mcp endpoint

  @core
  Scenario: R5 — Thin spur mcp stdio bridge forwards to the embedded /mcp server
    Given a local project served with MCP 2.0+ enabled
    When an agent runs spur mcp
    Then stdio JSON-RPC messages are forwarded to the embedded /mcp HTTP endpoint without duplicating handlers
