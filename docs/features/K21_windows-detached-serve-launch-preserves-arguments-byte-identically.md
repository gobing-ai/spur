# K21: Windows detached serve launch preserves arguments byte-identically

## Goal

The Windows branch of the detached `spur serve` launch passes every argument to the daemon
byte-identically. Today `defaultDetachedServeSpawn` (`packages/app/src/services/project-start.ts:81-103`)
embeds the argv in a `cmd /c start /b "" …` string and only doubles `"`, so `cmd.exe` expands `%NAME%`
(and `!NAME!` under delayed expansion) inside the quoted arguments — a project path containing `%` (legal
on Windows) is altered, or splices an environment value, before the daemon sees it.

Source: `/sp:dev-review packages --focus all` (2026-09-25), SECUA minor (Security). Extends K2's project
runtime robustness.

## Scope

**In:** the win32 branch of `defaultDetachedServeSpawn` and a new pure launch-spec builder in
`packages/app/src/services/project-start.ts`; unit tests in `packages/app/tests/services/project-start.test.ts`.

**Out:** the POSIX branch (`nohup` + `shQuote`, already correct); `resolveSpurServeCommand` argv
selection; the `DetachedServeSpawn` seam signature; a detached-launch API in `@gobing-ai/ts-runtime`
(0.5.7 has none — see task Q&A); CI on Windows.
