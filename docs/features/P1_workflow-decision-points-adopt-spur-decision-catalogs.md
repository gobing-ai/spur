# P1: Workflow decision points adopt spur decision catalogs

## Goal

Replace every AI decision point in Spur's shipped workflows with a catalog decision executed through the `spur decision` service, gradually and one decision point at a time, each only after `spur decision run` evidence shows its DecisionMaker is reliable enough. All workflow replacement work for decision catalogs lives in this feature; it is postponed until feature P ships and reliability evidence exists.

## Scope

**In scope**

- Workflow `decide` action accepts a catalog reference (`decision: <id>` + params/evidence) and executes through the feature P decision service, keeping the frozen schemaVersion 1 result row, evidence redaction/bounding and the `workflow.decideDecisionMaker` switch.
- Gradual adoption: one decision point per slice (`task-triage`, `failure-class`, `review-failure-class`, then any newly discovered decision points), each slice citing recorded `spur decision run` reliability evidence for its effective maker before it lands.
- End state: no shipped workflow declares an inline decide question; inline options are deprecated for one release with a warning, then removed.

**Out of scope**

- Anything feature P owns (catalogs, resolution, CLI noun, maker config).
- Choosing reliability thresholds in code; the evidence bar is an operator call recorded per slice.

**Entry condition**

Feature P done, and DecisionMaker reliability evidence recorded for the first decision point to migrate. Until then this feature stays in backlog.
