# M: Teams: declarative agent teams + Board module over existing message/drain/supervisor backbones

## Goal
Find the way to a first-class **Teams** capability that **consolidates** Spur's already-built
message / drain / supervisor / executor backbones into a declarative `agent.team.<id>` config
plus a Teams Board module — a capstone over existing machinery, not a rebuild.

- In:
  - `agent.team.<id>` config model + validation (0250)
  - member identity unification across inbox / spec / supervised process (0251)

  - Teams Board module + attach terminal; dedup of Observability's Inbox/Process tabs (0254, 0255)
  - team/message API surface decision (0256)

## Notes
### What this map consolidates (the backbones already exist)

| Requirement | Already built | Real gap |
|---|---|---|
| Message dispatch → inbox | `spur message send/inbox/reply/watch` → `InboxMessageDao`; `/api/messages*` | none |
| "Drain out" to agents | `spur agent run --drain` prepends inbox→prompt; supervisor default wrapper = `agent run --agent <id> --drain --continue` (self-draining loop) | no *team-level* lifecycle |
| Attach stdin/stdout/stderr | `SupervisorService` (ring buffer, `writeStdin`, lifecycle events); `POST …/stdin` + SSE `GET …/stream` | no terminal UI; line-framed (not PTY) |
| `agent.team` config | flat `agent.executors[]` presets + `.spur/agents/*.yaml` specs (grouped by `workspace`) | no first-class team object |
| Teams Board module | Observability already has Inbox + Processes tabs (system-wide) | no team-centric module/roster |

Core tension: `agent.executors` (named `{name,agent,model}` presets) and `.spur/agents/<id>.yaml`
(specs with `workspace`/`purpose`/inbox identity) are **two namespaces**; a team member must be both.

### Anchored decisions (from the discovery interview — treat as locked seeds)

- **DD-1 Team model** → *Roster in config → materialize specs.* `agent.team.<id>: {name, work_dir, members}`;
  `spur team up` generates one `.spur/agents/<member>.yaml` per member. Config = roster SSOT; specs = runtime units. (→ 0250, 0252)
- **DD-2 Message delivery** → *Self-draining wrapper loop.* Each member runs `agent run --agent <id> --drain --continue`
  (already the supervisor default); the "scheduler" only keeps it alive + handles autostart. Decentralized. (→ 0253)
- **DD-3 Attach fidelity** → *Line-framed SSE + stdin now; PTY opt-in later.* Reuse SupervisorService + SSE + xterm.js;
  a real PTY behind a per-member `interactive:true` flag is deferred to fog. (→ 0255, 0256)
- **DD-4 Board surface** → *New `Teams` module + migrate Inbox/Process tabs out of Observability.*
  Observability stays the system-wide telemetry view. (→ 0254)

### Decisions so far

- [0250 Team config schema](docs/tasks2/0250_team-config-schema-shape-of-agent-team-id-name-work-dir-memb.md) — `agent.team` = `Record<teamId, {name, work_dir, autostart?, members[]}>`; members are a **string-or-object union** (bare executor name, or `{executor, id?, purpose?, workspace?, model?, autonomy?, systemPrompt?, command?, autostart?}`); executor resolves **executors-first, raw-agent fallback**; autostart = **team default + per-member override**. Materializes to `AgentSpec` (ticket ### Design). _Id derivation superseded by 0251 → `<teamId>-(member.id ?? executor)`, always prefixed._

- [0251 Member identity](docs/tasks2/0251_member-identity-unify-member-id-across-inbox-recipient-agent.md) — canonical member id = `<teamId>-<localId>` **always prefixed** (`localId = member.id ?? executor`); the four surfaces (inbox recipient, spec id, supervisor key, coding-agent type) collapse to **one identity + one derivation** (`memberId → spec.type` via the existing drain `--agent` rewrite); `ref: <existing-id>` aliases a legacy spec verbatim (shared inbox+process). Overrode 0250's bare-`member.id` draft.
- [0252 spur team up/down](docs/tasks2/0252_spur-team-up-down-materialize-roster-into-spur-agents-specs-.md) — provenance via **`spur:generated`** tag (marked specs regenerated/pruned; hand-authored + `ref:` untouched); `team up` = materialize locally + start-autostart-if-server-reachable; `team down` = stop-only (`--purge` removes generated); `status` groups by `team:<id>`; drift = roster ⇄ marked-spec diff. Surfaced: per-member `command` can't round-trip (route via `config.command` + supervisor fix); autostart env→config wiring handed to the lifecycle ticket.

- [0253 Team lifecycle over supervisor](docs/tasks2/0253_team-lifecycle-over-supervisor-self-drain-keep-alive-autosta.md) — keep-alive = **loop wrapper (persistent) + supervisor restart-on-crash** (loop: `drainPending → run → idle-sleep`); crash policy = **exp backoff (cap 30s) + max 5 retries → `errored`**; autostart = **derive from `agent.team.*.autostart` at boot + `team up`, env overrides**. Key fix: `--drain` must call the consuming `drainPending` (queued→injected), not `getInbox` — else the loop re-prepends forever.

_The remaining forks were locked in the discovery interview (above); this log gains one line per ticket (0254–0256) as it closes._

### Not yet specified (fog of war)

In scope but not yet sharp enough to ticket — each hangs on an open ticket above.

- **Team addressing / broadcast** — `spur message send --to team:<id>` fan-out vs per-member. Hangs on 0251 (identity).
- **PTY escalation (`interactive: true`)** — true agent-TUI fidelity (xterm + real pseudo-terminal). Deferred per DD-3; revisit after line-framed v1 (0255).
- **Cross-work_dir teams** — 0250 sets `work_dir` at team level with an optional per-member `workspace` override; whether a team should *span* multiple work_dirs as a first-class concept stays open (hangs on a real use case).
- **Attach security** — who may write stdin / read the stream once `spur serve` is network-exposed? Not yet sharp.
- **Orphaned processes across `spur serve` restarts** — 0253 re-spawns autostart members on boot, but children from a prior serve (in-memory registry) aren't reaped; needs a process-group kill or a pid ledger. Hangs on implementation.

### Out of scope

Consciously ruled beyond this destination — does not graduate from fog.

- **Rebuilding the message / drain / supervisor / executor backbones.** This effort *consolidates* them; the plumbing stays.
- **BYOK / LLM model hosting or routing** beyond the existing `agent.executors` model tags. Spur wraps agents; it is not a model platform.
- **Remote / distributed agents across machines.** Spur is local-first; teams are local processes in a work_dir.
- **Non-coding-agent executor types.** Members are coding agents (claude/codex/omp/…).

### Proposed Teams Board tab set (Robin's requested frontend proposal — refined in 0254)

1. **Roster** — teams → members, live status, `start/stop/up/down` controls; selection drives the other tabs.
2. **Terminal** — attach to the selected member: live stdout/stderr (SSE) + stdin line-send (0255/0256).
3. **Messages** — selected member's inbox + a dispatch composer (`message send`), plus the global recent feed.
4. **Activity** — agent lifecycle + message-event timeline (reuses the system-event tap).
