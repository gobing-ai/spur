# I15: dev-idea follow-up ledger: deferred follow-ups and discovery findings never vanish

## Goal

Make an idea-pipeline run account for everything the idea and its discovery produce, not only the one feature it plans. Each deferred follow-up and each out-of-scope discovery finding must end up filed as a feature, linked to an existing one, or excluded with a recorded reason. The handoff report shows all three outcomes.

## Scope

- In:
  - Prompt and doc contract (already landed 2026-11-21): `[deferred: excluded — …]` and `[deferred: follow-up — …]` dispositions, discovery findings recorded as inventory items, feature-create filing follow-ups into `.spur/run/<runId>-idea-followups.json` behind a fail-closed shape and id gate.
  - A deterministic completeness check `checkFollowupLedger(report, ledger)` beside `checkInventoryCoverage`. Every follow-up item (a bare `[deferred:]` counts as follow-up) has exactly one ledger row whose featureId resolves, and no excluded item is filed.
  - `finalizeIdeaHandoff` enforces that check (fail closed) and its report adds "Follow-ups filed" (id → `/sp:dev-plan --feature <id>`) and "Excluded" (item → reason) sections. The single next command for the main feature stays.
  - An E2E proof: an idea fixture with one follow-up, one excluded item and one discovery finding runs end to end and leaves a repeatable receipt.
- Out:
  - Running the full pipeline for each follow-up inside the same run (follow-ups are filed as backlog features with Goal/Scope only).
  - New public `spur` nouns, verbs or flags. The ledger is found by run-folder convention.
  - Changing AC-coverage semantics: deferred items stay exempt from this feature's AC coverage.

## Acceptance Criteria

- [ ] R1 — Every follow-up inventory item has exactly one resolvable ledger row
- [ ] R2 — Excluded inventory items are never filed and are reported with their reason
- [ ] R3 — Handoff finalization fails closed on an incomplete follow-up ledger
- [ ] R4 — The handoff report lists filed follow-ups and excluded items
- [ ] R5 — An E2E idea run files follow-ups and discovery findings and leaves a receipt
