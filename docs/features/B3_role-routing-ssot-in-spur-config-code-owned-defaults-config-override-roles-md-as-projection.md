# B3: Role routing SSOT in spur config: code-owned defaults, config override, roles.md as projection

## Goal
Move the role → tier/stages routing contract's source of truth from the plugin markdown file
(`plugins/sp/references/roles.md`, regex-parsed by the CLI at runtime) into the Spur CLI itself:
code-owned defaults in `packages/config`, an optional per-project `agent.roles` override in the
config schema, and roles.md demoted to a parity-gated projection for fast agent/human reads.
## Scope
In:

- `DEFAULT_AGENT_ROLES` code constant in `packages/config` (the four roles with tier + stages,
  values identical to today's roles.md — zero behavior change) and an `agent.roles` config schema
  key (optional; closed vocabulary — re-tier/re-stage only, never invent roles).
- `loadAgentRoles()` resolution order: project config → code defaults; the markdown walk-up parse
  is deleted, not shimmed (defaults equal current values, so the cut is behavior-preserving).
- roles.md as a projection: parity assertion in `plugins/sp/tests/roles.test.ts` (roles.md
  tier/stages == DEFAULT_AGENT_ROLES) on top of the existing closure tests.
- `config/config.example.yaml` commented `agent.roles` block; dated ADR entry for the SSOT move.

Out:

- New roles or tier names (the 0536 closed vocabulary stays closed).
- Changes to resolution semantics (cheapest-eligible ladder, stage floors, escalation) — this
  feature moves WHERE the map lives, not how it is consumed.
- Per-project role customization beyond re-tier/re-stage (no project-local role invention).
