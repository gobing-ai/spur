# A31: Global CLI logo suppression and machine-output banner policy

## Goal

Give every Spur invocation an explicit global way to suppress startup decoration while guaranteeing
that machine-readable JSON output begins with JSON and remains safe for automation.

## Scope

**In scope**

- Register `--no-logo` as a public global Commander option.
- Centralize startup-banner selection at the CLI composition root.
- Suppress the startup logo for explicit `--no-logo` and automatically whenever the invocation
  contains a command's `--json` option; preserve the existing `--quiet`/`--silent` behavior.
- Cover root help, default human output, option placement, JSON output, and programmatic dispatch.
- Update the CLI surface design and public-surface consent record.

**Out of scope**

- Per-command copies of `--no-logo`.
- A config key or environment variable for logo policy.
- Suppressing command-owned diagnostic, staleness, narrowing, or report banners.
- Changing JSON payloads, envelopes, exit codes, or the banner-free `main()` programmatic API.

## Acceptance Criteria

```gherkin
Feature: Global CLI logo suppression and machine-output banner policy

  @core
  Scenario: R1 — The CLI exposes one global no-logo option
    Given the Spur CLI root command
    When a user requests top-level help
    Then `--no-logo` is listed once as a global option
    And the option is accepted before or after a noun and verb

  @core
  Scenario: R2 — Explicit no-logo suppresses startup decoration
    Given a command that normally renders the Spur startup logo
    When the user invokes it with `--no-logo`
    Then the startup logo is not written to stdout
    And the command's normal human-readable output and exit code are unchanged

  @core
  Scenario: R3 — JSON mode suppresses the startup logo automatically
    Given any Spur command that declares a `--json` option
    When the user invokes that command with `--json` and without `--no-logo`
    Then no startup logo precedes the command output
    And stdout starts with the command's machine-readable JSON document

  @core
  Scenario: R4 — Human mode retains the startup logo by default
    Given a normal CLI invocation without `--no-logo`, `--json`, `--quiet`, or `--silent`
    When the executable entry point runs
    Then the Spur startup logo is written once before command output

  @core
  Scenario: R5 — Banner policy has one composition-root owner
    Given noun modules independently declare their own command options
    When startup-banner policy is inspected
    Then the policy is owned by the CLI composition root
    And no noun module re-declares `--no-logo` or implements its own logo suppression

  @edge
  Scenario: R6 — Programmatic dispatch remains free of startup decoration
    Given a caller invokes `main()` directly instead of the executable entry point
    When a command is dispatched with or without `--no-logo`
    Then `main()` writes no startup logo
    And Commander still validates the global option normally

  @edge
  Scenario: R7 — Similar option names do not suppress the logo accidentally
    Given an invocation contains an option token other than exact `--no-logo`, `--json`, `--quiet`, or `--silent`
    When startup-banner policy is evaluated
    Then the logo remains enabled unless another exact suppression token is present
```
