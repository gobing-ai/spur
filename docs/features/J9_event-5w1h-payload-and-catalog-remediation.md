# J9: Event 5W1H payload and catalog remediation

## Goal
Make every cataloged System Event self-describing on the 5W1H contract I6
[0597] wrote: per-event presentation (not per-source inheritance), a real
what-changed payload on `*.updated`, and readable `workflow.*` rows.
## Scope
- In:
    - Add `PlanningEvent.field` and populate `data` on `task.updated` /
      `feature.updated` so a `--section Solution` write carries what changed
      (0597 §2, §6). `from`/`to` stay transition-only.
    - Move `SYSTEM_EVENT_CATALOG` from source-inherited `metadataFields`
      (12 shapes for 71 events) to per-event declarations (G6).
    - Author descriptions; stop shipping `describeEvent` mangles (G5).
    - Thread `workflowName` + `nodeLabel` + `kind` on engine-native
      `workflow.*` rows (0597 §7) so the Board does not render raw uuids.
    - A two-sided catalog↔`docs/design/event-tracking.md` matrix gate
      (0597 §9) — audit-only until emitters are fixed, then fail-closed.
    - Who/Why payload fields (`actor`/`trigger`) on the families 0597 G3/G4
      named, to the extent the emitter already has the value.
- Out:
    - Generating the catalog from the design doc (0597 decided: gate, not codegen).
    - Envelope v2 shape changes (`actionable-observability-context.md` owns that).
    - A new History board module. `TasksTab` / `JobsTab` refactor.
    - Anything under `spur task` (F92).
    - New CLI nouns.
## Acceptance Criteria
```gherkin

  Scenario: R1 — *.updated carries what changed
    Given a `spur task update <wbs> --section Solution` write

    And a status-only transition still uses `from`/`to` and does not invent a field
```
