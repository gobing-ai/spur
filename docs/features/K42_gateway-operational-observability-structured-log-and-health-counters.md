# K42: Gateway operational observability: structured log and health counters

## Goal

Make the always-on gateway diagnosable without adding state: a structured JSON-lines log for proxy failures, upstream starts and routing refusals, and live counters in `/api/health` rendered by `spur self status`.

## Scope

**In scope**
- JSON-lines log under the gateway log directory with a size cap: upstream start/adopt/restart, 502 failures with dialed addresses, prefix collisions, host-guard and CSRF refusals. The log lives at `~/Library/Logs/spur/gateway.events.jsonl` on darwin and `~/.config/spur/logs/gateway.events.jsonl` elsewhere. Gateway MCP call events are emitted by K41 task 1383 through the same event seam.
- In-memory counters since process start in `/api/health` (requests, 4xx/5xx, upstream restarts per project) and their rendering in a new additive machine-scoped `gateway` section of `spur self status`.

**Out of scope**
- A gateway database or event bus (ADR-151 keeps the gateway stateless).
- Shipping logs to external services.

## Acceptance Criteria

```gherkin
Feature: Gateway operational observability: structured log and health counters

  @core
  Scenario: R1 — Gateway failures and routing decisions are logged as structured lines
    Given a running gateway
    When an upstream fails to start, a prefix collides, or a request is refused by the host guard or CSRF check
    Then one JSON line per event is appended with timestamp, kind, project identity and reason, and the file never exceeds its size cap

  @core
  Scenario: R2 — Health exposes live counters rendered by self status
    Given a gateway that has served traffic
    When spur self status --json runs
    Then it reports request, error and per-project upstream restart counts since gateway start

```
