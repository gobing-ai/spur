# 05 Features — Spur

Feature decomposition for Spur. Each leaf is a single deliverable mappable to one `tasks` WBS item
with a clear acceptance check. Status reflects the current codebase — verify against code before
relying on a row (99 §6.6).

Legend: ✅ done · 🔶 partial (MVP, depth pending) · ⏳ planned · 💤 deferred (needs design).

This doc is the **index** over the `docs/features/` satellites (constitution §4.5). It carries two
views of the same features: the engine/capability decomposition below (hand-curated headline rows +
acceptance), and the **ID tree** that `spur feature` owns. Both point at the same
`docs/features/<id>_<slug>.md` satellites; the satellite is the source of truth (§4.5 rule 3). Edit
order is detail-first then index (§4.5 rule 5 / T9): update the satellite via `spur feature`, then
`spur feature refresh` regenerates the ID tree.
