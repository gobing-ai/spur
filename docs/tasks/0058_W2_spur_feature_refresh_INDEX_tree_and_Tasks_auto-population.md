## 0058. "W2: spur feature refresh — INDEX tree and Tasks auto-population"

### Background

Design §4.3, B03/B04/B06. INDEX renders the ID-encoded tree in tree-command style with status + links.


### Requirements

R1. INDEX.md full regeneration, deterministic, tree view with per-node status and markdown links.
R2. ## Tasks rewritten only between auto-gen markers; task files never touched.
R3. Golden-file tests.


### Q&A



### Design

Authority: design §4.3 (INDEX renders the ID-encoded tree, `tree`-command style, per-node status +
markdown link; full regeneration, deterministic ordering; feature `## Tasks` rewritten only between
auto-gen markers; task files never touched), B04 (links auto-populated from task `feature_id` edges).


### Solution

1. INDEX renderer in FeatureService: corpus scan → sort by ID (depth from length, lexicographic within
   level) → tree-drawing output with status badge + relative link per node → `docs/features/INDEX.md`.
2. `## Tasks` populator: scan registered task folders for `feature_id` edges → per-feature table (WBS,
   name, status) → `replaceMarkerRegion` via MarkdownDocument (0042); everything outside markers
   untouched (byte-compare test).
3. Golden-file tests for both outputs using the real corpus fixture + synthetic multi-depth fixtures.
4. Wire as `spur feature refresh` in the 0056 command file. Same commit: `04 §7.2`. Gate: ≥90%.

### Review

**SECU verdict: FAIL → PASS** (verified + fully implemented 2026-06-14 via `/rd3:dev-verify 0058 --force --fix all`)

As shipped, `FeatureService.refresh` was a **pure stub** (`return { index: '', tasksUpdated: 0 }`) — no INDEX
render, no `## Tasks` populator, no CLI subcommand, no golden tests. All of R1/R2/R3 UNMET. Built the full
feature during the fix-pass, and fixed a blocking marker-convention bug found along the way.

**S — Security:** Read-mostly. INDEX + feature writes go through `atomicWriteAsync` (crash-safe temp+rename,
DD-05); task names are pipe-escaped before going into the markdown table; no injection surface.

**C — Correctness / architecture:**
- R1 ✓ `refresh` → `renderIndex`: corpus scan, sort by ID (depth = length, lexicographic within level),
  `tree`-style connectors (`└──`/`├──`), per-node `[status]` badge + relative markdown link →
  `docs/features/INDEX.md` via `atomicWriteAsync`. Deterministic (two refreshes byte-identical — tested).
- R2 ✓ `## Tasks` populated via `MarkdownDocument.replaceMarkerRegion('Tasks', table)`: scans `tasksDir`
  for `feature_id == id` edges → `| WBS | Task | Status |` table (WBS-sorted) → rewrites ONLY between the
  auto-gen markers; everything outside (and every task file) is byte-preserved (tested). Empty → `_No
  linked tasks._`.
- R3 ✓ Golden-file tests: INDEX tree shape + determinism; Tasks marker-region rewrite with byte-preserved
  outside content; task-files-never-touched; no-tasks placeholder.
- CLI ✓ `spur feature refresh` (`--folder`/`--json`, exit 0/1) wired into the 0056 command file.
- **Marker bug fixed:** the 0042 primitive + the real corpus use `<!-- AUTO-GENERATED by spur feature
  refresh -->` markers, but the 0054 template + 0056 `templateContent` emitted `<!-- BEGIN_TASKS -->` AND
  omitted the `## Tasks` heading — so `replaceMarkerRegion` would throw on a freshly-created feature.
  Corrected the template + `templateContent` to the canonical `## Tasks` + `AUTO-GENERATED` markers.

**U — Usability:** `--json` returns `{ index_path, tasksUpdated }`; human output summarizes lines + count.
