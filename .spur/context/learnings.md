## Key Learnings

- **System Events completeness requires producer-driven tests, not direct bus emits.** Task 0221 expanded the catalog and added tap/SSE tests, but `apps/server/tests/upstream-system-events-wiring.test.ts` directly emits `rule.*`/`workflow.*` names onto the server bus, so it can pass while real producers never reach `spur serve`. Future observability work must execute real server-owned producers or explicitly document/bridge the CLI subprocess boundary. (bug-766)
- **Dogfood report contract is unenforced outside Claude Code.** `sp:dogfood-testing/references/report-template.md` owns the mandatory sections (Testee, Execution Summary, `### 3. Monitor Ledger`, Issues, Findings with feasibility tags, `── Dogfood Summary ──` footer), but super-coder's terminal gate #5 only greps for file *existence* under `docs/dogfood/`, and Codex sessions have no `Skill()` mechanism to force the template. Result (2026-07-02): reports 0178–0181 each invented a different ad-hoc format. Also note `docs/dogfood/` is **gitignored** (`.gitignore:155`) while ~40 pre-ignore reports remain tracked — new reports silently never reach the repo even though committed task References link to them. (bug-749)
- **Dogfood verdict vocabulary drift hides testee failure.** When the testee is a pipeline and the pipeline FAILs but the task is finished manually, the honest testee verdict is FAIL (or PARTIAL) with recovery notes — not "PASS with manual recovery". Five consecutive task-pipeline implement timeouts (bugs 742/744/746/748) were all reported as PASS variants, masking a 100% pipeline failure rate.
- **`.spur/tasks/` is a SYMLINK to `config/tasks/`** (dir symlink — `.spur/tasks -> config/tasks`; same inode confirmed). So `section-matrix.yaml` and the task templates have exactly ONE physical copy. `loadSectionMatrix` (`apps/cli/src/commands/task.ts:655`) resolves `.spur/tasks/section-matrix.yaml` (project-local) FIRST, then `config/tasks/section-matrix.yaml` (bundled fallback) — but the symlink makes both the same file, so a single edit to `config/tasks/section-matrix.yaml` takes effect immediately. Don't maintain two copies. **Section-matrix gotcha:** the `review` variant gates by status; `Requirements` is optional only at `todo/wip/testing/done` (added 2026-06-28 for dogfood-followup review tasks that grow implementation scope) — a Requirements section on a `backlog` review task still trips the L2 "not allowed" warning by design.
- **`.spur/workflows/` is a SYMLINK to `config/workflows/`** (same inode — confirmed `ls -li`). `config/workflows/` is the SSOT seeded into projects by `spur init`; editing either path updates both. Don't `cp` between them or maintain two copies. The five canonical workflows: `basic`, `feature-dev` (single-task fast-lane FSM), `feature-lifecycle` + `task-lifecycle` (the canonical status FSMs with `spur (task|feature) check` guards), `planning-pipeline` (front-half: phasing→feature-id→design-gen→design-approval→handoff) + `task-pipeline` (execution: precheck→implement→test→review→approve→verify→record→done). Validate any edit with `spur workflow validate <path>`.
- **Migrated `rd3:` artifacts may carry stale command surface.** `feature-dev.yaml` shipped with `/rd3:` prefixes, the retired `dev-new-task` step, and three non-existent dev-run/dev-verify flags (`--verify`, `--channel`, `--force` — the real ones are `--mode`, `--agent`, `--bdd`, `--next`). When reviewing migrated config/skills, grep for `/rd3:` and cross-check every flag against the command's `argument-hint`. The task-pipeline calls `spur task verdict` + `spur task record` (both exist; `task verdict` is NOT yet in the CLAUDE.md CLI-surface listing — a doc drift, not a pipeline bug).
- **Unit-test logger standard:** Spur mutes the shared `@gobing-ai/ts-infra` logger globally through Bun's test preload `tests/setup.ts` (`bunfig.toml` `[test].preload`). Do NOT add per-file `initializeLogger()` or `setLoggerMuted()` calls for normal tests; rely on the preload. If a test needs to assert logging, inject a recording logger directly into the unit under test instead of unmuting the global logger.
- **Coverage output path standard:** Spur's canonical coverage output dir is root `.coverage/`, never `coverage/`. Bun defaults bare `bun test --coverage` to `coverage/`, so `bunfig.toml` pins `[test].coverageDir = ".coverage"` and runnable coverage commands still pass explicit coverage-dir flags (`.coverage` from root, `../../.coverage` from `apps/cli`). Do not hide `coverage/` in `.gitignore`; if it reappears, it should be visible as a wrong artifact.
- **Stop-on-first verification pattern:** Tests for traversal-short-circuit features must include a later failing rule and assert it is not reached. A one-finding fixture where the second rule passes does not prove stop-on-first behavior; it would pass even if traversal stayed exhaustive.
- **TSDoc export rule is intentionally active:** `.spur/rules/quality/tsdoc-exports.yaml` must keep `every-export-has-tsdoc` enabled. If it flags exported symbols, including under `vendors/`, fix the missing TSDoc comments rather than disabling or excluding the rule.
- **Regex-rule scope convention:** `@gobing-ai/ts-rule-engine` regex rules currently use a loose include/exclude matcher that strips `**/` and `*` then does substring matching. Deep globs like `apps/**/src/**/*.ts` can collapse into fragments that never match real app paths. For portable regex rules in Spur, prefer stable path fragments (`src/`) plus explicit excludes (`**/tests/**`, `**/dist/**`, `**/node_modules/**`), and verify with a planted probe before trusting the rule.
- **ts-runtime 0.3.2 compatibility in Spur:** legacy `getFs`/`setFileSystem`/`NodeFileSystem` still export, but `NodeFileSystem` no longer satisfies the public `FileSystem` interface used by Spur services/tests, and `FileSystem.mkdir` was replaced by `ensureDir`. For Spur code typed as `FileSystem`, use `createNodeFileSystem()`; keep `setFileSystem(new NodeFileSystem())` only for the legacy global `getFs()` path.
- **Spur rule preset `extends` resolves a name to EITHER a category dir OR a same-named preset file → collision = circular dep.** A preset file `strict.yaml` (`name: strict`) that does `extends: [strict]` resolves `strict` to ITSELF (the preset), not the `strict/` category dir, yielding "Circular preset dependency detected: strict → strict". Fix: never name a preset file the same as a category dir it extends — name the preset differently (e.g. `strict-check.yaml` extending the `strict/` dir). The default presets work because `recommended-pre-check`/`recommended-post-check` names differ from the `typescript`/`structure`/`boundary`/`quality` category dirs they extend.
- **CLI help routing is command-scoped after the one-layer migration (ADR-013).** `-h/--help` is still parsed globally, but dispatch must prefer a command-specific renderer when a command path exists (`spur <command> --help`, `spur <command> help`, `spur help <command>`). New top-level command modules must export `helpText()` next to their `run*Command` implementation; `index.ts` imports with aliases (`helpText as ruleHelpText`) and keeps only the compact global command index.
- **Absorbing ts-libs rules into spur-new: most typescript/* rules are NOT portable.** ts-libs is a LIBRARY monorepo (`packages/db|infra|runtime|utils`) whose rules police INTERNAL package boundaries (drizzle in packages/db, fetch behind packages/infra/api-client, spawn behind packages/runtime, ESM dist-extension fixer). spur-new is an APPLICATION monorepo (`apps/** + packages/{app,config,contracts,domain,plugin-sdk}`) that CONSUMES those as published `@gobing-ai/ts-*` facades — so those boundaries are enforced upstream and the paths don't even exist here. Portable & absorbed (default): bun-tooling (no npm/pnpm/yarn, enforce-bun-test, no-vitest — but EXCLUDE `apps/server/**/*.cf.ts` + `vitest.cf.config.ts`, the sanctioned Workers Vitest suite), output-boundaries (no-console/no-raw-stdout — Spur's only sink is ts-utils echo/echoError, no excludes needed), protected-files (secrets/unsafe-git/env). Opt-in `strict-check` (allowlisted): http/runtime fs+spawn boundaries (allow `apps/server` fetch entrypoint, `apps/cli/.../agent.ts` $EDITOR Bun.spawn, sanctioned node:fs sites in workflow/agent-service/migrations). Explicitly REJECTED: `no-github-workflows` (ts-libs forbids CI; Spur legitimately ships ci.yml+publish.yml), `no-direct-process-env` (config-from-env is Spur's design), all db-boundaries (Spur's own boundary/dao-boundary.yaml covers it). A rule that scans rule-definition YAML for forbidden TOOL words (npm/pnpm/yarn) self-matches its own pattern/description → exclude both canonical `config/rules/**` and scaffold/symlink `.spur/rules/**` from such regex rules.
- **Bundled rule presets live upstream:** `@gobing-ai/ts-rule-engine` ships portable presets under `rules/` (recommended, spur-dev + typescript/structure/quality categories), exposed via `bundledRulesRoot()` / `listBundledRuleFiles()`. The CLI must NOT hardcode rule YAML (the old project did, in `builtin-rules.ts`); rule content belongs with the engine that defines the evaluators. `spur init` copies them to `~/.config/spur/rules` and `rule run` also appends `bundledRulesRoot()` as a lowest-priority fallback.
- **Rule-root resolution order** (rule.ts `ruleRoots`): SPUR_RULES_PATH → local `.spur/rules` → global `~/.config/spur/rules` (or `SPUR_GLOBAL_RULES_DIR`) → bundled fallback. Setting `SPUR_GLOBAL_RULES_DIR` explicitly SUPPRESSES the bundled fallback — that's the hermetic-run / test-isolation signal. The loader dedupes by relative path (highest-priority root wins), so seeding global + bundled fallback never double-counts.
- **Recommended preset split:** `recommended-pre-check` owns cheap static source-shape rules, including `surface` (`cli-register-pattern`, `cli-json-output`), because they do not need test/build artifacts. `recommended-post-check` is reserved for artifact-dependent/heavier quality checks (`quality`: coverage gate, TSDoc export rule).

Bare per-rule severity rows are misleading because `error` means configured severity, not an active finding. Use `spur rule run --verbose` to verify actual findings.
- **`rule run` fails loud on zero rules:** `filteredRules.length === 0` returns exit 1. A constraint gate that silently evaluates nothing is the worst failure mode; tests that asserted exit 0 on an empty project were encoding the bug and were updated.
- **Two scope dialects coexist by evaluator (matchMode):** `rg` + structured `forbidden-import` + `import-boundary` + `tsdoc-export` use `matchMode: 'glob'` → deep globs (`apps/**/src/**/*.ts`) work. BUT `secrets-scanner` and `regex` (and legacy `forbidden-import {patterns:[]}`) use `matchMode: 'loose'` → `matchesAny` strips `**/` and `*`, so `apps/**/*.ts` collapses to `apps/.ts` and matches ZERO files. **Loose-matcher rules MUST use path FRAGMENTS** (`apps/`, `packages/`, `scripts/`) with suffix-style excludes (`/tests/`, `.test.ts`), never deep globs. Check the evaluator's `matchMode` in ts-rule-engine `src/evaluators/*.ts` before choosing include shape.

- **[2026-06-14] The `FileSystem` interface (ts-runtime) has NO `rename` — a file "rename" = `atomicWriteAsync(newPath)` + `deleteFile(oldPath)`.** `spur feature move` (0061 cascade rename) uses this: read old, rewrite `id` frontmatter, atomic-write to the new `{newId}_{slug}.md` path, delete the old path. - **[2026-06-14] Subtree re-ID for a feature move: target root = `allocateId(newParent)` (next free digit ≤9, skips taken siblings); each descendant maps `oldId → newRootId + oldId.slice(movedId.length)` (preserve the relative suffix).** Collision guard: a mapped id collides only if it exists in the corpus AND is not itself in the moved subtree (`byId.has(newId) && !movedSet.has(newId)`) — this catches a pre-existing DEEP id (e.g. a stray B11 when moving A1→B1 maps A11→B11) that `allocateId` (which only scans direct children) wouldn't see. - **[2026-06-14] The workflow engine's available capability vocabulary (default host = what `workflow validate` uses): ACTIONS `note`, `shell`, `event.emit`; GUARDS `shell`, `always`, `never`, `action-ok`. Spur adds at RUNTIME (registerSpurBuiltins, not the validate host): `agent.run`, `rule.check`, `file.exists/read`, `hitl.confirm/select/input`, `http.request`.** `workflow validate` checks STRUCTURE, not kind-registration — so a YAML using `agent.run`/`hitl.confirm` validates true even though those aren't in the validate host. ## Key Learnings

- **Workflow authoring: note stub pattern for dry-run-safe shell gates.** When a workflow has a real shell gate (e.g. `bun run autofix && bun run spur-check`) that is too slow/heavy for dry-run shape verification, stub it as a `note` action and leave a comment showing the real `shell` action shape. The dry-run proves the state graph and transition paths; swap in the real shell action for actual use. The `action-ok` guard always passes on a `note`, so the happy-path short-circuit (check→verify) still fires during the dry-run, proving the guard order is correct.
- **iterationBound accounts for ALL transitions, not just loop iterations.** A workflow with a 7-state linear prefix (6 transitions) plus a fix loop (2 transitions per cycle) needs an iterationBound that covers the prefix + N cycles. For feature-dev: 6 linear transitions + 8 fix cycles × 2 = 22, so bound=20 allows ~7 fix cycles. Set conservatively high for real use.
- **note actions always succeed → action-ok always passes after a note.** Dry-running a check state with a note stub means the `action-ok` guard fires on the check→done/verify edge every time. This is correct for shape verification (proves the short-circuit edge works) but means you can't dry-run the check→fix path without replacing the note with a shell that can fail. To test the fix loop path, the shell gate must be real (or a `shell: command: exit 1` stub).
- **The engine has no built-in `slash` or `agent` action kind.** LLM-driven or slash-command steps can only be modeled as advisory `note` actions that emit the command string. For a workflow to be truly executable (not just advisory), a custom `slash` action kind registering against `sp:workflow-run` or an `agent` action kind is needed — but requires an engine enhancement, not just YAML authoring.

- **V8 func coverage + classes:** a class with NO explicit constructor (even without `extends`) leaves a synthetic default constructor that V8 counts as a function but never marks "hit", capping `% Funcs` (e.g. a 3-real-method class shows 75% = 3/4). ## Key Learnings

- **Workspace vs root engine resolution can diverge (stale bun link):** root `node_modules/@gobing-ai/ts-dual-workflow-engine` is a leftover global-link symlink to the local ts-libs build, while workspaces resolve the published version from the `.bun` store. Reading the root path can show UNRELEASED code. Always verify what a workspace actually executes with `import.meta.resolve('<pkg>')` run from inside that workspace.
- **The workflow engine silently ignores unknown `WorkflowRunOptions` fields.** A Spur flag wired to an engine option that the *published* engine doesn't know becomes a silent no-op (e.g. `--dry-run` on engine 0.3.11 executed actions anyway). Behaviorally verify every new engine-backed flag with a probe that MUST fail if the option is ignored (e.g. a failing shell action under dry-run).
- **`ts-rule-engine` already fires run-level events:** `rule.run.start`, `rule.eval.start`, `rule.eval.done`, `rule.eval.error`, `rule.run.done` (dot-names, `rule.` prefix). RuleService already wires `new RuleEngine({ events })` for `--verbose` (rule-service.ts:408-447). - **Workflow engine event bus is per-run, not per-service:** inject `EventBus<WorkflowEngineEvents>` via `WorkflowRunOptions.events` on `runFile()`; the engine `WorkflowService` constructor takes only `(host, persistence)`.
- **Enriching typed EventBus payloads with optional fields is non-breaking** for subscribers (only the engine emits; extra fields don't break destructuring). Prefer optional-field enrichment over parallel near-duplicate event names.
- **Optional engine tables: only swallow expected missing-table errors.** Spur trace readers may need to tolerate a not-yet-released engine table such as `action_runs`, but DAOs must rethrow other DB failures (locked DB, malformed query, adapter failure) instead of returning empty timelines.
