# Daily UI Review Checklist

Use this in 5–10 minutes before shipping or requesting review.

## 1. Task clarity
- [ ] Can a first-time user tell what this screen is for in a few seconds?
- [ ] Is the primary action or primary information obvious?
- [ ] Did we include only functionality we can actually support now?

## 2. Hierarchy
- [ ] Is there one clear visual entry point?
- [ ] Are secondary and tertiary elements quieter?
- [ ] Are we using weight/contrast/spacing, not just font size?
- [ ] Could any label be removed or merged into the value?
- [ ] If something important is weak, can competitors be de-emphasized instead?

## 3. Spacing and layout
- [ ] Do closer elements belong together?
- [ ] Are group-to-group gaps visibly larger than internal gaps?
- [ ] Are any gaps ambiguous?
- [ ] Are we filling width without a content reason?
- [ ] Does each region use an appropriate width instead of one forced grid?
- [ ] Are values drawn from a spacing/sizing scale?

## 4. Typography
- [ ] Are type sizes drawn from a small scale?
- [ ] Is body/UI text comfortably legible?
- [ ] Is line length controlled?
- [ ] Does line-height fit the text size?
- [ ] Are icons/text aligned optically or by baseline where appropriate?
- [ ] Are colored links used only when they need emphasis?
- [ ] Is centered text limited to short blocks?

## 5. Color
- [ ] Do colors belong to defined shade ramps?
- [ ] Are neutral colors coherent with the product personality?
- [ ] Is contrast sufficient for reading and controls?
- [ ] Is secondary text on colored surfaces intentionally color-matched rather than generic grey/opacity?
- [ ] Is any status communicated by color alone?

## 6. Depth and surfaces
- [ ] Do shadows imply a consistent elevation model?
- [ ] Are borders necessary?
- [ ] Could spacing or surface color replace some borders?
- [ ] Are radii consistent with the personality?
- [ ] Is overlap used only when it improves the composition?

## 7. Images
- [ ] Are source images high enough quality?
- [ ] Is text readable over every likely image?
- [ ] Are icons shown near their intended visual size?
- [ ] Are screenshots readable without squinting?
- [ ] Are user uploads safely cropped and constrained?

## 8. States
- [ ] Empty
- [ ] Loading
- [ ] Error
- [ ] Disabled
- [ ] Hover/focus/active
- [ ] Overflow / long text / large numbers
- [ ] Small and large viewport behavior

## 9. Polish
- [ ] Do empty states help the user act?
- [ ] Are accents/background decorations subordinate to content?
- [ ] Is the UI over-carded or over-bordered?
- [ ] Are repeated values converted to tokens/components?
- [ ] Did we solve structural problems before adding decoration?

## Final test
Hide the brand color and decorative imagery mentally. If the screen still has strong hierarchy, clear grouping, readable typography, and coherent actions, the foundation is good.
